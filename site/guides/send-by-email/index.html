Send a drawing by e-mail from GridScalr

Open the marked-up drawing as an unsent draft in your local mail client, with the PDF already attached.

Short answer

Choose File → Send & share → Send by e-mail…. GridScalr opens the same drawing-export dialog as Drawing PDF…, then starts a new, unsent draft in your local mail client with <project>-markups.pdf attached. Nothing is sent automatically, and the source drawing is never modified.

Pick the drawing and export it

The e-mail action does not take a shortcut past the export settings. Page range, crop area, visible layers, labels, the calibration line, the legend, optional reader layers and review annotations follow the same rules as any other drawing PDF. Hidden items and hidden layers are never attached. When the export has finished, the mail client opens with the file already on the draft.

What the mail client receives

The draft is addressed to nobody until you add a recipient. Add the subject and message in your usual client, then send it there. On Windows, GridScalr prefers Simple MAPI through the default MAPI client, usually Outlook, and falls back to outlook.exe /a. On macOS it drives Mail through osascript, which may ask for Automation permission the first time. On Linux it prefers xdg-email --attach and falls back to Thunderbird. Your client may still show its own profile, security or attachment prompt; that prompt belongs to the client.

When no draft opens

If no mail client opens, GridScalr names the saved PDF and offers Show file, so a failed launch is never silent. You can then attach the file yourself in whatever mail client you use. The attachment is written to the app cache folder mail-outbox, which keeps the ten most recent attachments and deletes older ones at the next launch or export.

Webmail and the browser build

Webmail in a browser is not supported, because a mailto: link cannot carry an attachment. Send by e-mail is a desktop action and is disabled in the browser fallback. Nothing is sent automatically, the project file is never attached, and closing the draft without sending is your choice, not an app failure.

Common mistakes

  • Expecting the draft to carry a recipient; the recipient is always yours to add.
  • Choosing webmail and expecting the PDF to be attached by a mailto: link.
  • Assuming a client prompt means the export failed; read the prompt and confirm it in the mail client.
  • Sending before checking the page range, crop and visible layers in the export dialog.

Questions

Does GridScalr send the e-mail?

No. It opens an unsent draft in your local mail client and leaves sending, recipients and any client prompt to you. Nothing leaves the machine automatically.

Can I use webmail such as Gmail in a browser?

No. A mailto: link cannot carry an attachment, so webmail in a browser is not supported. Use a desktop mail client, or export the PDF and attach it yourself.

Where does the attached PDF come from?

From the drawing-export dialog, written to the app cache folder mail-outbox. The ten most recent attachments are kept and older ones are deleted at the next launch or export. The project file and the source drawing are never attached or modified.
