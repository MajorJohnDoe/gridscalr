What is an operation card?

The sheet that tells the next technician how a system is put together, set and looked after.

Short answer

An operation card is a drawing sheet that documents one HVAC system: its equipment, duct and pipe runs, sensors, control points and settings. It stays with the building so the next technician can understand, operate and maintain the system without reconstructing it from memory.

What the card documents

An operation card, or driftkort in Swedish, describes a system rather than a room. It shows the units, fans, coils, dampers, valves, sensors and control points that belong together, and it records the values a technician needs in order to run and service them. The drawing is schematic, not architectural: position on the page matters less than the relationship between components.

Who uses it

Operations technicians use the card during inspection, adjustment and fault tracing. Property managers use it as part of the building's technical documentation. Contractors use it when a component is replaced or a control strategy changes. Because all three read the same sheet, an out-of-date card is worse than none: the card needs a revision table and a clear owner.

What a complete card contains

  • A title block with property, system, unit designation, date, author and revision.
  • A schematic with the system's equipment, ducts or pipes, sensors and control points.
  • Setpoints and operating values that a technician must know.
  • A revision table so changes can be traced.
  • Notes for maintenance, access and known deviations.

Drawing the card in GridScalr

GridScalr creates an operation card sheet from a built-in template on A3 or A2. The title block and revision table are part of the sheet, fields are edited on the canvas or in the sheet form, and schematic symbols are drawn on drawing layers. The exported PDF keeps the title block and fields even when every layer is hidden, and the text is searchable.

Template sheets are marked Sheet · not to scale. They do not need calibration, because they document a system rather than measure the building.

Keeping the card useful

A card is only useful if the next reader can trust it. Keep one system per card, name the unit consistently, and update the revision row whenever a component or setpoint changes. Put site notes on their own drawing layer so they can be hidden without losing the schematic, and export only the layers the recipient should see.

Common mistakes

  • Filling the title block after the drawing, so the card has no revision.
  • Mixing measurements into the schematic layer, which makes later edits harder.
  • Using the page number as the unit designation instead of the system's own tag.
  • Exporting with hidden layers that the recipient still needs.

Questions

Is an operation card the same as an as-built drawing?

No. An as-built records the installed geometry. An operation card is a schematic for operating and maintaining one system, with settings and control points.

Does an operation card need a scale?

No. It is a template sheet marked not to scale. Calibration belongs on measured drawings, not on schematic cards.

Can the title block be exported with the drawing?

Yes. Sheet fields and the revision table are drawn into the PDF even when every layer is hidden.
