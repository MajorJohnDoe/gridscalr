#### Completed

- No production code, dependency, workflow, schema or version change.

#### Decisions

- Phase 1 is audit-only. No production fix was made because there is no P0.
- No P0 and no P1. Eight P2 and eight P3 findings; all are assigned to phases
  2–5 or to a proposed new issue.
- The page loads two CSP policies: the Tauri header and a static meta tag in
  `index.html`. Both are enforced; the meta tag is the stricter one for
  `script-src` and the looser one for `connect-src` (F-028).
- Bundled Web Workers do not receive the configured CSP header and do not
  inherit the page meta policy, so the worker boundary is outside the policy
  (F-029).
- `core:default` is broader than the app needs; the minimum set is
  `core:event:default`, six explicit window permissions and `dialog:default`
  (F-030).
- The write guard does not yet protect a managed copy's `originalPath` (F-031).
- `glib 0.18.5` remains an accepted Linux-only advisory tracked by
  [#21](https://github.com/MajorJohnDoe/gridscalr/issues/21). The four additional
  Rust advisories are unmaintained crates with no known vulnerability.
- The ten npm moderate advisories are development-only; the production audit is
  clean (F-039).
- No new test was added in this phase. A CSP or network regression test added now
  would either fail or encode the current inconsistency, so it belongs to the
  phase that fixes it (F-028, F-029) or to phase 5 (F-032).

#### Findings

- F-028 P2 — Two page CSP policies; production keeps the dev
  `localhost:1420` HTTP/WS origins; missing hardening directives; phase 2.
- F-029 P2 — PDF.js and Tesseract workers are outside the configured CSP;
  phase 2.
- F-030 P2 — `core:default` grants unused menu, tray, image, path, webview and
  app permissions; phase 2.
- F-031 P2 — The write guard ignores `DocumentRef.originalPath`; phase 3.
- F-032 P2 — No byte limit on project or file reads; phase 3.
- F-033 P2 — Package extraction can write 16 GiB without disclosure or a free
  space check; phase 3.
- F-034 P2 — An untrusted project can reference any local path; phase 3 plus a
  documentation note.
- F-035 P2 — GitHub Actions use mutable major tags in the release build;
  phase 4.
- F-036 P3 — Windows path guarantees are not tested on Windows; phase 3.
- F-037 P3 — Test-only IPC commands are shipped; phase 2.
- F-038 P3 — `style-src 'unsafe-inline'` is forced by two static declarations;
  phase 2.
- F-039 P3 — Development-only minimatch advisory; phase 4.
- F-040 P3 — Accepted glib advisory and four unmaintained Rust crates; phase 4.
- F-041 P3 — A crashed save leaves project data in a temporary sibling;
  phase 3.
- F-042 P3 — IPC error details expose absolute paths; phase 2 or a small
  follow-up.
- F-043 P3 — PDF export embeds a wall-clock time, so the byte-comparison test is

  change.

#### Decisions

- The Tauri response header is the only production page policy. A meta policy in
  the built HTML would be a second, silently intersecting policy.
- `script-src` keeps `blob:` because `tauri://localhost` has an opaque origin and
  PDF.js wraps its worker in a second blob module. Removing it needs a different
  worker bootstrap, not a smaller source list.
- `dialog:allow-message` is not granted; the app draws its own confirm/message
  dialogs.
- `core:window:allow-internal-toggle-maximize` is kept for title-bar
  double-click. `allow-close` is dropped because the close flow calls `destroy()`.
- `freezePrototype` stays `false`: pdf-lib assigns `PDFHeader.prototype.toString`
  and the page throws under a frozen `Object.prototype`. Reproduced in Chromium
  and in the packaged WebKitGTK smoke test, which never left the boot screen.
  This matches the note already in `docs/architecture.md`.
- `npm run test:csp` runs the OCR worker in Chromium; the packaged smoke test
  covers the same workers in the real webview on all three CI platforms.

### Phase 3 — Harden filesystem paths, symlinks, managed copies and package extraction

- Issue: [#169](https://github.com/MajorJohnDoe/gridscalr/issues/169)

- Schema: unchanged (25). No app version change.

#### Completed

- Added the shared Rust `path_guard` module: absolute resolution, canonical
  symlink/junction handling, `\\?\` and UNC normalisation, case folding, hard
  links, managed-folder containment, empty and drive-relative rejection, bounded
  reads and stale temporary cleanup. `commands.rs`, `project_write.rs`,
  `source_copy.rs` and `package.rs` now use it instead of three near-copies.
- Closed F-031: `sourceDocumentPaths()` adds every non-empty `originalPath` and
  the managed-copy folder; both guards refuse a destination inside that folder.
- Closed F-032: project reads are capped at 256 MB, source reads at 1 GiB and
  backup writes at 256 MB with a structured `fileTooLarge` error; the browser
  fallback checks the picked file size; `source_find_by_hash` has a total-byte
  budget.
- Closed F-033: the extraction limit is now 2 GiB uncompressed, 1 GiB per entry
  and 2 GiB for the ZIP. The dialog shows the unpacked size and extraction
  checks free space with a 64 MiB reserve (`disk_space.rs`).
- Closed F-034: a localized, dismissible banner names out-of-folder references
  and offers **Copy into project** and **Relink**; the project doctor lists the
  same warning. The reference is never blocked.
- Closed F-041: the next save removes stale generated temporary siblings older
  than ten minutes, never one owned by the running process.
- Hardened package entry validation: control characters, drive, UNC and
  backslash spellings are rejected during inspection *and* before writing.

#### Modules

- `src-tauri/src/path_guard.rs`, `path_guard_tests.rs`, `disk_space.rs`;
  `commands.rs`, `project_write.rs`, `project_backup.rs`, `source_copy.rs`,
  `package.rs`, `lib.rs`, `Cargo.toml`
- `src/io/limits.ts`, `src/io/writeGuard.ts`, `src/io/projectFile/paths.ts`,
  `src/io/platform.ts`, `src/io/platformError.ts`
- `src/features/sourceStorage/outsideReferences.ts`, `referenceWarning.ts`,
  `controller.ts`, `index.ts`
- `src/features/projectPackage/{ipc,model,ui,controller}.ts`
- `src/app/projectDoctorFlows.ts`

#### Decisions

- The guard compares case-insensitively on every platform. Two distinct
  case-variant files are refused as ambiguous rather than assumed different.
- A relative path is anchored to the current directory; a drive-relative path is
  rejected instead of guessed, and a UNC spelling is never anchored locally.
- `libc` (unix) and `windows-sys` (windows) are used only for the free-space
  probe. Both were already in the lock file.
- The out-of-folder reference is a warning with the existing copy/relink
  actions, not a block: reference mode is a documented product feature.
- `originalPath` stays protected after **Detach from source** because the file
  on disk still exists; detaching only clears provenance in the project.

### Phase 4 — Dependency and advisory gate

- Issue: [#170](https://github.com/MajorJohnDoe/gridscalr/issues/170)

#### Completed

- Added `npm run check:dependencies`: `npm audit` for the frontend and
  `cargo audit` for `src-tauri`, with a reviewed
  `security/dependency-allowlist.json`.
- Every entry needs an advisory ID, a stated reason, `reviewedAt` and a
  `reviewBy` expiry. An expired entry, a stale entry, a missing reason or a
  duplicate entry fails. The gate fails closed with an explicit message when an
  audit report cannot be read after retrying.
- Threshold: npm and Rust findings at moderate or above are blocked unless
  accepted; low/info are reported only. Rust `unsound`, `unmaintained` and
  `yanked` findings require an accepted entry; `notice` is reported.
- Fixed the `minimatch` advisory with a scoped `overrides` entry to `^11.0.1`.
  `npm audit` is clean; F-039 closed.
- Accepted the glib soundness advisory and the four unmaintained Rust crates
  with reasons and a 2027-02-11 review date. glib stays tracked by
  [#21](https://github.com/MajorJohnDoe/gridscalr/issues/21); F-040 accepted.
- Added the CI **Dependency advisory gate** job and made **Release build**
  depend on it. The job prints the summary, writes the step summary and uploads
  the raw reports and `gate-result.json`.
- Refreshed `package-lock.json` to the 0.23.0 root version; `check:versions`
  now checks the lock root as well.
- Closed Dependabot PRs [#149](https://github.com/MajorJohnDoe/gridscalr/pull/149)
  and [#148](https://github.com/MajorJohnDoe/gridscalr/pull/148): neither was

#### Decisions

- Moderate is the blocking threshold for both ecosystems, not only high and
  critical. A moderate advisory is either fixed or written down.
- A Rust vulnerability without a CVSS score is treated as high, and the gate
  never passes an unreadable report.
- The `minimatch` override is a tested temporary exception outside ESLint's
  declared range (F-048). It avoids carrying a development-only moderate
  advisory in the allowlist indefinitely.
- Accepted entries expire; renewal is an explicit quarterly review, not an
  automatic extension.
- `--npm-report` / `--cargo-report` can replay a saved report offline, but CI
  always reads the live advisory databases.

## Decisions already taken

- Autosave is an app-level preference: default on, interval 15/30/60 seconds,
  and pause for the current session.

- Read-only becomes true view-only with an explicit **Take over to edit**.

## Workflow

Use [`conductor-prompt.md`](conductor-prompt.md). One fresh worker per phase,
independent defensive review before merge, and a green `main` before the next
phase. Phase 1 is audit-only: produce a threat model and P0/P1/P2 findings with
follow-up issues. Do not make production changes in phase 1 unless a P0 requires
it.
