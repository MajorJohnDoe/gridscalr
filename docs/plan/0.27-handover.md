## Phase 8 — Edit-safe shell rendering

- Issue: #244
- PR: #246
- Commit: 8982c69
- Schema: unchanged (26)

### Completed

- A `"save"` render requested while an editable field inside the shell has focus
  is deferred until that field's `blur`; the source chips and page badges refresh
  then instead of the field being removed mid-edit.
- An immediate render while a field has focus runs on the next tick and restores
  focus, value, selection/caret and the nearest scroll-container offset. A field
  rebuilt by the render is matched by `id`, then `data-role`, then structural
  path plus tag/type; value and caret are written only for a stable match, and a
  control the user moved to is never displaced.
- A render requested from inside a running render is queued and replayed after
  it, never nested.
- `clear()` in `src/ui/dom.ts` is one atomic `replaceChildren()`, so a stray
  nested clear cannot throw `NotFoundError`.
- `isEditableTarget()` compares `isContentEditable` strictly; the predicate was
  returning `undefined` where it promised a boolean.
- `Tab` out of a Properties field keeps working: a `focusout` inside the shell
  defers the following `change` render by one tick so the next focus target
  exists before the panel is rebuilt.

### Modules

- `src/ui/editSafeRender.ts` (new, 197 lines) — render scheduling: background
  deferral, immediate-render tick, focusout deferral, re-entrant queue,
  `requestShellRender()` / `disposeShellRender()`.
- `src/ui/editFieldSnapshot.ts` (new, 230 lines) — focused-field snapshot,
  rebuild matching and value/caret/scroll restore.
- `src/ui/panels.ts` — `renderChrome(refs, actions, reason)` is the single shell
  paint entry and delegates to the scheduler.
- `src/ui/shell.ts` — re-exports `disposeShellRender` so the app keeps one shell
  entry point.
- `src/ui/dom.ts` — atomic `clear()`, strict editable predicate.
- `src/app/App.ts` — wiring only (`renderAll(reason)`, one disposal line); 1093
  of its 1094-line budget, no budget change.
- `tests/editSafeRender.test.ts` (new), `scripts/canvas-regression.mjs` (step 13).

### Decisions

- `renderChrome()` owns the scheduler call instead of `App.renderAll()`
  duplicating it, so no future caller can repaint the shell around the edit-safe
  path. `App.renderAll()` therefore forwards the store reason and stays at one
  line of wiring; this keeps `src/app/App.ts` inside its existing budget with no
  `--update`.
- The module map in `0.27.md` listed `src/ui/editSafeRender.ts` only. The
  scheduler and the field snapshot were split into two files when the first draft
  reached 409 lines, which is over the ADR 0013 hard limit. `panels.ts`,
  `shell.ts` and `App.ts` are the wiring surface; no business logic was added to
  an integration file.
- The snapshot writes the typed value back only when the rebuilt field matched by
  `id` or `data-role`. Restoring text on a structural match alone could overwrite
  another item's label after a selection change.
- No framework, no virtual DOM and no per-field reconciliation; the shell still
  renders from state.

### Findings

- F-102 (accepted) — a background source check waits for the focused field to
  blur, so a missing/changed warning can be delayed until the user leaves the
  field. Phase 9 (#243) removes the synthetic render entirely.
- F-103 (deferred) — a rebuilt field without an `id` or `data-role` keeps focus
  but not the caret; add stable keys when Properties is next touched.

### Open questions

  probe **before** the temporary file or folder exists. A new

## Phase 2 — Unused managed drawings

- Issue: #241
- PR: [#250](https://github.com/MajorJohnDoe/gridscalr/pull/250)
- Commit: 3c8732a
- Schema: unchanged (26)

### Completed

- The project doctor's source section offers one explicit **Remove unused
  drawings…** action. It lists every unreferenced managed file with its size and
  the total, and is disabled for a read-only project and when the folder has no
  unused copy.
- Confirming re-lists `<project>.drawings/` and rebuilds the reference set from
  the open project immediately before the removal, so a copy that became
  referenced or vanished is skipped and included in the reported skip count.
- `source_remove_managed_copies` replaces the single-name delete. It validates
  every requested leaf name before moving anything, re-reads the folder, and only
  moves a currently listed regular PDF directly in the project's own drawings
  folder. A symlink, subfolder, non-PDF or the project file is refused.
- Removal never hard-deletes. Each file goes to the operating system trash when
  that is available; otherwise the batch is moved into one timestamped
  `.<project>.<pid>.<stamp>.<counter>.removed` folder beside the project. The
  Rust report carries the destination per file and the folder path, which the
  doctor shows after the action (`cleanupTrash` / `cleanupFolder`).
- F-017 is fixed.

### Modules

- `src-tauri/src/source_cleanup.rs` (274 lines) — batch removal types,
  `verify_removable`, the shared fallback folder, `remove_managed_copies_with`
  with an injected trash backend and the `source_remove_managed_copies` command.
- `src-tauri/src/source_cleanup_tests.rs` — 10 tests for classification, the
  trash/fallback decision and the guards.
- `src/features/projectIntegrity/sourceFiles.ts` — `removeManagedCopies` IPC and
  the removal report types.
- `src/features/projectIntegrity/sourceAvailability.ts` — re-check and result
  aggregation (`trashed`, `folder`).
- `src/features/projectIntegrity/sourceUi.ts` — the explicit action and the
  post-removal notice.
- `tests/projectDoctorSources.test.ts` — classification, race, confirmation,
  failure and rendering tests.
- `src-tauri/Cargo.toml`, `src-tauri/Cargo.lock`, `README.md`,
  `CONTRIBUTING.md`, `THIRD_PARTY_NOTICES.md` — the trash dependency, MSRV and
  notices.
- `docs/{user-guide,workflows,limitations,architecture}.md`, `README.md`,
  `docs/plan/foundation-findings.md` — the visible action and the limit.

### Decisions

- **One batch command, not one call per file.** The reference set is rebuilt
  immediately before the request and the Rust side re-reads the folder inside it,
  so no project mutation can slip between the check and a removal. A per-file IPC
  loop would need the renderer to pass the fallback folder back to Rust on every
  later call and validate that path again.
- **The fallback folder is inside the project folder.** It is created once per
  request with `unique_sibling`, so the rename never crosses a volume and a
  concurrent cleanup cannot collide. The `.removed` suffix is excluded from
  `temp_cleanup` because deleting it automatically would destroy the folder the
  user may still want.
- **The action is always rendered in the unused section**, disabled rather than
  hidden, so a read-only project and an empty folder both explain the state.
- **`trash` 5.3 for the OS integration.** It is MIT, uses the `windows` 0.62
  crate the shell already locks, and adds only `urlencoding` transitively. It
  requires Rust 1.87, so the declared `rust-version`, README and CONTRIBUTING now
  say 1.87.0 and `Cargo.lock` is format 4. Reimplementing the platform trash
  (Windows shell, macOS NSFileManager, freedesktop spec) would be far more
  untested unsafe code for no gain.
- No schema change and no automatic cleanup on save, load or a timer.

- F-017 — fixed by this phase.
- F-106 — next step corrected: the unused-drawings action inventories only

- F-107 (accepted, P3) — a fallback `.removed` folder is reported once and never

## Phase 3 — Managed-copy replacement hygiene

- Issue: #236
- PR: [#251](https://github.com/MajorJohnDoe/gridscalr/pull/251)
- Commit: e4d92e0 (implementation)
- Schema: unchanged (26)

### Completed

- Replacing a managed-copy PDF copies the new pick into `<project>.drawings/`
  and verifies its SHA-256 before any project field changes. The document stays
  managed and `originalPath`/`originalSha256` describe the new pick. A failed
  copy or checksum mismatch aborts the replacement; the old document and its
  file are untouched.
- `applySourceReplacement()` derives `storage` and provenance explicitly for the
  in-place and split branches. A reference result clears the replaced managed
  provenance instead of inheriting it, and the serialized project no longer
  carries the old absolute path.
- The previous managed file is never deleted. After a managed→managed
  replacement it is an unreferenced copy that the doctor lists; the referenced
  new copy is protected by canonical path. Explicit **Remove unused drawings…**
  remains the only removal path.
- F-085 fixed: `plannedRepairs()` offers only kinds whose repair contributes at
  least one planned change; the doctor loop uses that list for the dialog and the
  applied subset. The repair section reads per-kind counts from the one combined
  plan, so the per-kind `planRepair()` clones are gone. Apply still refuses an
  empty plan.
- F-084 closed as no-recursion by design. The flat drawings folder is the
  contract; a Rust test pins the nested-file behavior and the limit is in
  `docs/limitations.md`.
- The 0.27.0 plan's phase 3 exit wording and its "no automatic deletion" decision
  were corrected to match: replacement leaves the previous copy for the doctor.
- F-088 fixed; F-108 recorded for the TIF case.

### Modules

- `src/features/sourceStorage/replacementCopy.ts` (new, 74 lines) —
  `preservesManagedStorage()` and `prepareReplacementDocument()`.
- `src/features/sourceStorage/index.ts` — public surface for both.
- `src/features/pageModel/replacement.ts` — one `replacementDocument()` builder
  for storage and provenance normalization.
- `src/app/replacementFlows.ts` — wiring only: prepare a managed replacement
  after the dialog, abort when the copy fails, one checkpointed apply.
- `src/features/projectIntegrity/{repairPlan,repair,index,doctor,repairUi}.ts` —
  plan-derived availability and shared counts.
- Tests: `tests/pageReplacement.test.ts`, `tests/robustness/sourceStorage.test.ts`,
  `tests/projectDoctorSources.test.ts`, `tests/projectDoctorRepairPreview.test.ts`.
- Docs: user guide, limitations, project-file, findings, plan.

### Decisions

- **Preserve managed storage on replacement.** Replacement is a source change,
  not a request to weaken source protection. The copy is made after the mapping
  dialog and before the checkpoint, so cancelling never copies and a failure
  never half-applies. A checksum mismatch aborts rather than accepting a copy.
- **Never delete the old copy.** It becomes an orphan for the doctor's explicit
  cleanup. This matches the release rule that only the explicit action removes a
  managed file, after a fresh reference check.
- **A split replacement copies too.** When only some pages map, the new document
  is still a managed copy of the pick; the superseded old document keeps its own
  managed file for the unmatched pages.
- **TIF stays a reference.** A TIF carries its derived PDF in the project and
  the inventory, consolidation and package paths handle regular PDFs only.
  Copying the `.tif` would create a file the cleanup cannot see (F-108).
- **F-085 availability reads the plan, once per dialog iteration.** The
  "repairable" issue filter still uses `availableRepairs()` because it describes
  the code, not the plan.

### Findings

- F-084 — closed (no recursion by design).
- F-085 — fixed.
- F-088 — fixed.
- F-108 (accepted, P3) — a managed TIF, which the app cannot create, would
  degrade to a reference on replacement; extend the inventory, packaging and cap
  before making managed TIF a real mode.

### Open questions

- None blocking. The managed replacement relies on the project having a path,
  which every managed document already requires; an inconsistent project shows a
  localized message and leaves the source unchanged.

### Checks

- Local: `npm test -- --run` (147 files, 1401 tests), `npm run test:robustness`

## Phase 7 — Colour-scan storage decision and TIF/OCG limits

- Issue: #238
- PR: [#258](https://github.com/MajorJohnDoe/gridscalr/pull/258)
- Commit: 26b8901 (decision, docs and test) plus this handover commit
- Schema: unchanged (26)

### Completed

- **Colour-scan decision recorded and deferred with a budget.** ADR
  [0015](../adr/0015-colour-scan-storage.md) keeps the embedded derived PDF in
  0.27.0 and states the accepted budget: **8 MiB of project JSON per 25 MP
  colour page and 160 MiB of embedded derived PDFs per project** (twenty 25 MP
  sheets, or eight full A1 sheets at 300 DPI), against the 256 MB project limit
  and the 48-million-character undo budget. The numbers are measured, not
  guessed: a 25 MP (about A2 at 250 DPI) RGB line-art sheet is 71.5 MiB decoded,
  5.4 MiB Flate and 7.2 MiB of base64; a 69.7 MP A1 at 300 DPI is 199.4 MiB
  decoded, 15.1 MiB Flate and 20.1 MiB of base64; the same 25 MP sheet as 1-bit
  is 10 KiB. The 256 MiB decoded-raster guard, not the 400 MP pixel cap, limits a
  colour page to about 89 MP, and its worst case produces ~341 MiB of base64, so
  the 256 MB limit is the hard stop.
- The target design is reference TIF plus **a rebuildable derived-PDF cache**
  keyed by TIF SHA-256 and converter version, which removes the bytes from the
  JSON. It needs schema 27 and is deferred to
  [#256](https://github.com/MajorJohnDoe/gridscalr/issues/256). A downsampled
  raster (loses line work and OCR detail), a JPEG re-encode (needs a new encoder,
  is lossy, and still lives in the JSON) and a managed `.tif` copy (F-108, the
  copy/inventory/packaging paths are PDF-only) were rejected with reasons in the
  ADR.
- **CCITT passthrough pinned.** New `tests/tiffStoragePolicy.test.ts` asserts,
  for a real G4 fixture, that every `/CCITTFaxDecode` stream equals its source
  strip byte for byte, that the summed stream bytes equal the source strip bytes,
  that the derived PDF is source + PDF structure only (no decoded raster growth),
  and that a decoded colour page stays `/FlateDecode /DeviceRGB` with no
  `/DCTDecode` and is embedded base64 exactly as the ADR describes.
- **OCG decisions recorded.** ADR
  [0016](../adr/0016-optional-content-export-shape.md) keeps one OCG per layer
  with per-page marked content and closes F-023 as an accepted trade-off
  (per-page groups would multiply the reader list by the page count and cannot
  express the schema 26 hierarchy). It decides F-087 is **ours to fix**: ISO
  32000-1 defines nesting as the array form, which pdf.js implements, while the
  heading dictionary is an Acrobat extension. The writer change is deferred to
  [#257](https://github.com/MajorJohnDoe/gridscalr/issues/257) with its real
  blocker named: in the array form the heading is not selectable, so a group
  layer that owns items needs a name rule for its own content, and the form must
  be verified in Acrobat as well as Firefox.
- **Limits documented where the user meets them.** `docs/limitations.md` splits
  the single TIF paragraph into the decoding limits and a separate colour-scan
  budget, and names every finding: RGBA over white (F-089), 16-bit to 8-bit
  (F-090), packed-sample predictor refusal (F-092), tiled JPEG (F-093),
  abbreviated old-style JPEG (F-094), the CMYK marker convention (F-095). The
  user guide's **TIF drawings**, **A TIF is rejected** and drawing-export
  sections say the same in task language, including the flat Firefox layer list.
  `docs/project-file.md` explains why the derived PDF is the one large base64
  field and links ADR 0015.

### Decisions

  new failure mode (cache missing, scan moved) and no format record. 0.27.0 is

- **The budget is an operating limit, not a refusal.** A new import-time refusal

- **No silent downsampling and no JPEG re-encode.** A measurement app must not

- **F-087 is ours, and is still not a rush change.** Calling it an external
  viewer bug would be wrong — the array form is the standard — but swapping the
  form changes the group-owns-items presentation in every reader, so it gets a
  decision (ADR 0016) and a follow-up issue with the verification it needs.
