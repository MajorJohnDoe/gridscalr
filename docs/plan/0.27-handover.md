## Phase 8 — Edit-safe shell rendering

- Issue: #244
- PR: #246
- Commit: 8982c69
- Schema: unchanged (26)

### Completed

- A `"save"` render requested while an editable field inside the shell has focus
  is deferred until that field's `blur`; the source chips and page badges refresh
  then instead of the field being removed mid-edit.
- An immediate render while a field has focus runs on the next tick and restores
  focus, value, selection/caret and the nearest scroll-container offset. A field
  rebuilt by the render is matched by `id`, then `data-role`, then structural
  path plus tag/type; value and caret are written only for a stable match, and a
  control the user moved to is never displaced.
- A render requested from inside a running render is queued and replayed after
  it, never nested.
- `clear()` in `src/ui/dom.ts` is one atomic `replaceChildren()`, so a stray
  nested clear cannot throw `NotFoundError`.
- `isEditableTarget()` compares `isContentEditable` strictly; the predicate was
  returning `undefined` where it promised a boolean.
- `Tab` out of a Properties field keeps working: a `focusout` inside the shell
  defers the following `change` render by one tick so the next focus target
  exists before the panel is rebuilt.

### Modules

- `src/ui/editSafeRender.ts` (new, 197 lines) — render scheduling: background
  deferral, immediate-render tick, focusout deferral, re-entrant queue,
  `requestShellRender()` / `disposeShellRender()`.
- `src/ui/editFieldSnapshot.ts` (new, 230 lines) — focused-field snapshot,
  rebuild matching and value/caret/scroll restore.
- `src/ui/panels.ts` — `renderChrome(refs, actions, reason)` is the single shell
  paint entry and delegates to the scheduler.
- `src/ui/shell.ts` — re-exports `disposeShellRender` so the app keeps one shell
  entry point.
- `src/ui/dom.ts` — atomic `clear()`, strict editable predicate.
- `src/app/App.ts` — wiring only (`renderAll(reason)`, one disposal line); 1093
  of its 1094-line budget, no budget change.
- `tests/editSafeRender.test.ts` (new), `scripts/canvas-regression.mjs` (step 13).

### Decisions

- `renderChrome()` owns the scheduler call instead of `App.renderAll()`
  duplicating it, so no future caller can repaint the shell around the edit-safe
  path. `App.renderAll()` therefore forwards the store reason and stays at one
  line of wiring; this keeps `src/app/App.ts` inside its existing budget with no
  `--update`.
- The module map in `0.27.md` listed `src/ui/editSafeRender.ts` only. The
  scheduler and the field snapshot were split into two files when the first draft
  reached 409 lines, which is over the ADR 0013 hard limit. `panels.ts`,
  `shell.ts` and `App.ts` are the wiring surface; no business logic was added to
  an integration file.
- The snapshot writes the typed value back only when the rebuilt field matched by
  `id` or `data-role`. Restoring text on a structural match alone could overwrite
  another item's label after a selection change.
- No framework, no virtual DOM and no per-field reconciliation; the shell still
  renders from state.

### Findings

- F-102 (accepted) — a background source check waits for the focused field to
  blur, so a missing/changed warning can be delayed until the user leaves the
  field. Phase 9 (#243) removes the synthetic render entirely.
- F-103 (deferred) — a rebuilt field without an `id` or `data-role` keeps focus
  but not the caret; add stable keys when Properties is next touched.

### Open questions

- None blocking. The tick-based deferral relies on the browser settling the next
  focus target before the timer runs; the canvas regression covers `Enter` and
  `Tab` from a Properties field.

  `check:versions`, `check:file-budgets`, `check:modules`, `check:security`,

## Phase 9 — Source-status refresh without a synthetic save

- Issue: #243
- PR: #247
- Commit: 0117d76
- Schema: unchanged (26)

### Completed

- `SourceStatusMonitor` compares each completed check with the previous status
  set by document ID, state and storage. An unchanged poll updates `checkedAt`
  but sends no notification; a changed, missing or closed set still notifies.
- The monitor no longer calls `store.emit("save")` and never mutates the
  project. A source check is no longer presented as a project change.
- One `sourceStatus` subscription in `App` refreshes only the status bar chips
  and, while the Pages tab is mounted, the page badge rows, filter counts and
  card accessible names. Cards keep their thumbnails, listeners and any open
  page-rename field.
- A non-default Pages filter can change which pages match, so that case rebuilds
  the Pages panel only; it is not a shell render and does not use the store.
- F-102 is fixed. The edit-safe renderer comment no longer claims the source
  poll emits `"save"`.

### Modules

- `src/source/sourceStatus.ts` — status-set comparison and notify-on-change.
- `src/ui/sidebar.ts` — `refreshSourceStatusPanels()`: status chips plus Pages
  badges.
- `src/ui/pageList.ts` — `refreshPageStatusBadges()`, shared card aria helper and
  shared filter-bar builder; page-list file is 449 lines, under the 700 budget.
- `src/app/App.ts` — wiring only (one import, one field, one subscription, one
  disposal line); orphan docblocks removed to stay at 1090 of 1094 lines.
- `tests/sourceStatus.test.ts` — unchanged/changed notification, no store emit,
  and chip/badge integration.
- `src/ui/editSafeRender.ts` and `docs/plan/foundation-findings.md` — comment and
  F-102 status corrected.

### Decisions

- The targeted refresh does not go through `requestShellRender()`. A direct chip
  and badge patch cannot remove the focused field, so deferring it would only
  delay a source warning (F-102). No new store reason, event bus or full shell
  render was added.
- The monitor compares the status set, not `checkedAt`: a successful but
  unchanged check must not reach the UI.
- `SourceStorageController` keeps its own `sourceStatus` subscription for the
  source-changed banners, which are a separate surface from the chips and page
  badges.

### Findings

- F-102 — fixed by #243; no new findings.

### Open questions

- None blocking. The Layers panel has no source-status badge today, so the
  phase refreshes the Pages badges only.

## Phase 10 — Theme-driven Layers and Mätlager surfaces

- Issue: #245
- PR: #248
- Commit: 506c4d6
- Schema: unchanged (26)

### Completed

- `--surface-inset` and `--surface-inset-foot` are part of the token contract and
  declared in all five palettes. `layerTree.css` drives `.layer-section-rows` and
  `.layer-section-foot` from them; no palette literal remains for either surface.
- Medium Grey is pixel-identical to 0.26.0: rows `#2e3031ad` and footer
  `rgb(255 255 255 / 10%)`, which compute to `rgba(46, 48, 49, 0.68)` and
  `rgba(255, 255, 255, 0.1)`. All four visual baselines stayed at 0 diff pixels.
- Light Green uses its input inset (`#f1f5fa`) with the darker `#e6edf5` footer
  strip. Dark Grey, Jade and Navy each use their own inset value plus a 6% white
  footer strip, so the footer reads as a strip against the panel.
- Row hover, selected, inherited-hidden, drop-target and group styling are
  unchanged.
- `check:themes` now requires both tokens in every palette. A focused unit test
  guards the medium-grey literals and the token usage in `layerTree.css`, and the
  UI smoke test asserts the rendered surfaces in Light Green, System-light,
  Medium Grey, System-dark, Dark Grey, Jade and Navy, including row-name contrast.

### Modules

- `src/styles/layerTree.css` — section rows and footer use the new tokens.
- `src/styles/tokens.css` — semantic aliases for both surfaces.
- `src/styles/themes/{medium-grey,light-green,dark-grey,jade,navy}.css` — palette
  values, with medium grey keeping the historical literals.
- `scripts/theme-token-rules.mjs` (new, 114 lines) and
  `scripts/theme-token-rules.d.mts` (new) — pure palette rules.
- `scripts/check-theme-tokens.mjs` — runner only.
- `scripts/smoke-ui.mjs` — computed-style surface and contrast assertions.
- `tests/theme.test.ts`, `docs/testing.md`, `docs/plan/foundation-findings.md`.

### Decisions

- The tokens are declared in every palette instead of relying on the
  `tokens.css` alias, so a palette that forgets one fails `check:themes`. The
  aliases remain as the documented contract for an unknown `data-theme`.
- The pure rules moved to `scripts/theme-token-rules.mjs` (the pattern of
  `file-budget-rules.mjs` and `dependency-gate.mjs`) because importing the runner
  would execute the gate. No file-budget exception was needed.
- The rendered check compares computed colours and WCAG contrast instead of adding
  a Light Green baseline image: it is deterministic, needs no font or platform
  baseline, and leaves the four Medium Grey baselines untouched.
- Medium Grey keeps `#2e3031ad` and `rgb(255 255 255 / 10%)` verbatim rather than
  re-deriving them from `--input-sunken`, so the default look cannot drift.

### Findings

- F-104 (deferred, P3) — component CSS still carries jade-palette literals that
  only later `chrome.css` overrides mask; clean up with a CSS scan when that file
  is next touched.

## Phase 1 — Write caps, managed-copy cap and temporary cleanup

- Issue: #240
- PR: [#249](https://github.com/MajorJohnDoe/gridscalr/pull/249)
- Commit: 9bbec7f
- Schema: unchanged (26)

### Completed

- Package creation runs the documented 2 GiB uncompressed cap and a free-space
  probe **before** the temporary file or folder exists. A new
  `PackageError::TooLarge` carries the required size and the cap; both limits
  have localized messages. The destination-folder probe walks up to the nearest
  existing folder, so a folder that does not exist yet still sees its volume.
- The package options dialog shows the expected uncompressed size and
  recomputes it when the optional exports change. The controller refuses a
  known-too-large package before it asks for a path.
- `copy_to_project` applies `MAX_SOURCE_BYTES` before hashing or streaming and
  returns the already-localized `fileTooLarge` code. The size check runs before
  the drawings folder is created.
- Stale-temporary naming and the age/process guard moved to
  `src-tauri/src/temp_cleanup.rs`. A new `clean_project_temporaries` command runs
  after a successful project load and removes stale save siblings next to the
  project plus stale `.<name>.extract-<pid>-<stamp>` folders in the same folder.
  Extraction also cleans the destination folder before it creates a new staging
  folder. A `.<name>.previous-<pid>-<stamp>` folder is never deleted.
- In-scope fix: `PackageError` serialized `required_bytes`/`available_bytes` in
  snake_case, so the extraction free-space dialog always showed 0 and 0. The
  enum now uses `rename_all_fields = "camelCase"` and a test pins the wire
  format.

### Modules

- `src-tauri/src/temp_cleanup.rs` (new, 350 lines) — generated temporary
  patterns, the shared age/process guard, extraction-folder cleanup and the
  `clean_project_temporaries` command; the cleanup tests moved here from
  `path_guard_tests.rs`.
- `src-tauri/src/package_limits.rs` (new, 91 lines) — pure output cap and
  free-space decision with its own tests.
- `src-tauri/src/disk_space.rs` — `available_bytes_at()` for a not-yet-created
  destination.
- `src-tauri/src/package.rs` — `TooLarge` variant and mapping, `SpaceProbe`
  injection for the pre-write test, limit check and extraction cleanup call.
- `src-tauri/src/path_guard.rs` — cleanup removed (289 lines, 367 → 289);
  `too_large` is shared with the managed-copy check.
- `src-tauri/src/source_copy.rs` — `copy_to_project_limited()` with the
  documented cap.
- `src-tauri/src/{commands,project_write,lib}.rs` — import and command wiring.
- `src/features/projectPackage/{model,ui,controller}.ts` — estimate, dialog size
  line, `tooLarge` failure and the early refusal.
- `src/features/saveIntegrity/{files,index}.ts` — `cleanProjectTemporaries`
  wrapper; `src/app/projectSession.ts` calls it after a successful load.
- `tests/projectPackage.test.ts`, `tests/projectPackageUi.test.ts`,
  `file-budgets.json`, `AGENTS.md`, `docs/architecture.md`,
  `docs/limitations.md`, `docs/user-guide.md`, `docs/plan/foundation-findings.md`.

### Decisions

- The limit decision lives in `package_limits.rs`, not in the already oversized
  `package.rs`, so it is a pure function with its own tests and the legacy file
  only maps its result. The two existing reviewed Rust budgets were raised with
  `check:file-budgets --update` (`package.rs` 2289→2442, `source_copy.rs`
  538→577); no new exception was added and no new file is oversized.
- The cleanup entry point is one command called once after a successful load,
  instead of an extra write or store event in the open path. A cleanup failure is
  logged at `warn` and never changes the loaded project.
- Extraction-folder detection matches the generated shape alone
  (`.…extract-<pid>-<stamp>`) rather than one destination name, because after a
  crash the destination name may no longer be known. The process id is part of the
  name, so no mtime is consulted.
- `.previous-` folders are deliberately out of the cleanup: deleting one would
  destroy the folder the user replaced. Recorded as F-106.
- The package dialog estimate covers the known content only (project JSON,
  physical sources, README/headers). Optional exports are generated later and are
  named in the dialog copy; the Rust check still refuses the final total.

### Findings

- F-044, F-045, F-046 — fixed by this phase.
- F-105 (deferred, P3) — the `.lock-tmp` and `.deleted` suffix families are still
  never cleaned; they are small and outside the project folder.
- F-106 (accepted, P3) — a stale `.previous-` extraction folder is kept and is not
  reported anywhere yet; phase 2 (#241) is the right place to surface it.

### Open questions

- None blocking. The estimate can understate the final package when the optional
  exports are large; the user can still be refused by the Rust check, which now
  reports the required size and the cap.
