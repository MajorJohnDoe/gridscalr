# 0.28.0 — schema freeze and the 1.0 release candidate

**Status:** planned. Scope agreed on 2026-11-13; phases 1–8 to be cut as issues
before production code.
**Baseline:** 0.27.0, project-file schema 26.
**Epic:** to create.
**Milestone:** `0.28.0` (to create).
**Handover:** `docs/plan/0.28-handover.md` (create with the first phase).

0.28.0 is the **release-candidate release**. It makes the last schema change
before the 1.0 freeze, closes the two shipped bugs that are still visible to a
user, and converts the remaining manual release checks into gates. There is one
new drawing capability: none. Everything here is either a correctness fix, a
storage fix, or a check that stops regressing.

The release follows the conductor workflow in
[`conductor-prompt.md`](conductor-prompt.md): one fresh worker per phase, one
pull request per phase, defensive review against the PR head SHA, and a handover
update after every merge.

## Why now

- **Schema 27 is the last schema change allowed before 1.0.** The 1.0 gate
  requires the schema and migration promise to be frozen and documented. A
  colour-scan storage fix that arrives after the freeze is a schema 28, so it has
  to land now or wait past 1.0. [#256](https://github.com/MajorJohnDoe/gridscalr/issues/256)
  is the only remaining schema candidate, and the alternative is freezing a
  format whose worst page exceeds the 256 MB project limit.
- **Two shipped behaviours are wrong, not missing.**
  [#257](https://github.com/MajorJohnDoe/gridscalr/issues/257) makes every
  optional-content export read flat in Firefox and pdf.js, and
  [#237](https://github.com/MajorJohnDoe/gridscalr/issues/237) leaves the
  preflight **Relink…** unreachable in the exact case it was built for. Both are
  interoperability features that 1.0 claims to have.
- **Two 1.0 gate items are still manual.**
  [#55](https://github.com/MajorJohnDoe/gridscalr/issues/55) (accessibility and
  performance gates) and [#53](https://github.com/MajorJohnDoe/gridscalr/issues/53)
  (release-candidate hardening) are the difference between "we believe the
  foundation is stable" and "CI proves it".
- **One release artifact was never verified.** The macOS job in the release
  matrix has never completed; only DMG packaging is unverified
  ([#74](https://github.com/MajorJohnDoe/gridscalr/issues/74)).
- **One dependency alert is still open by decision.**
  [#21](https://github.com/MajorJohnDoe/gridscalr/issues/21) must end 0.28 as
  either fixed or formally accepted with an expiry, because the 1.0 gate admits
  no unaccepted alerts.

Phases 1–2 are independent and can land first; they are also the two cheapest
user-visible wins, so they should not wait behind the schema work.

Phases 3–4 are one decision cut into two shipments. Phase 3 changes the format
and the migration; phase 4 makes the cache live. Phase 3 must not merge with a
dead field: if 4 slips, 3 must still leave a project that opens, renders and
exports, with `embeddedPdf` present exactly as today.

Phase 5 is independent. Phase 6 is a workflow run, not code, and can happen any
time after the tag exists — but it must happen before 1.0 is declared.

Phase 7 is a decision, not necessarily an upgrade. Phase 8 closes the release.

## Decisions and non-goals

- **0.28.0 is the release candidate; 1.0.0 follows only if it passes.** No new
  drawing capability goes into either. This is the decision the plan is built
  on and the one to confirm first.
- **Schema 27 is the last schema change before the freeze.** After phase 3, a
  further storage change means a schema 28 and a deliberate unfreeze. The
  migration corpus and the compatibility promise extend to 27 and stop.
- **CCITT G3/G4 passthrough stays byte-for-byte.** The derived cache is for
  decoded colour pages. A lossless passthrough page keeps exactly today's bytes
  and never acquires a cache entry.
- **The derived cache is a cache, never a source of truth.** It is keyed by TIF
  SHA-256, converter version and page count; deleting it costs a rebuild, never
  data. A missing TIF with a present cache still opens.
- **No new storage mode and no new source rule.** Reference and managed copy
  remain the two modes; the cache lives beside the project the way managed
  drawings do, and packages still carry one form of each drawing.
- **The OCG change is a serialization change, not an export redesign.** One OCG
  per exported layer, the same marked content, the same `/ON` state. Only
  `/Order` changes shape.
- **No accessibility redesign.** Phase 5 adds checks and fixes what they find;
  it does not restructure the shell or introduce a component library.
- **No dependency upgrade for its own sake.** Phase 7 takes the smallest change
  that closes the advisory, or records an acceptance with an expiry. A general
  Tauri upgrade is its own issue.
- **No documentation freeze dodge.** [#54](https://github.com/MajorJohnDoe/gridscalr/issues/54)
  and [#57](https://github.com/MajorJohnDoe/gridscalr/issues/57) are the 1.0
  documentation items; 0.28 keeps the documentation it changes accurate and
  defers the full translation pass deliberately, not silently.

## Risks

- **The derived cache can desynchronise from the scan.** Key it on the TIF hash
  plus converter version plus page count, and treat a key mismatch as "rebuild",
  never as "trust it". A stale cache that renders an old revision is worse than
  no cache.
- **A missing TIF with a missing cache is a dead page.** That path needs a real
  dialog and a test, not a thrown error. It is the case the 1.0 promise is most
  likely to hit in a customer folder.
- **The OCG name rule has no free option.** Every choice (repeated name, renamed
  heading, content outside the heading) is visible in some reader. Decide it with
  a real export open and record the trade-off in ADR 0016, rather than picking the
  one that serializes most neatly.
- **Reader verification is manual and slow.** Acrobat, PDF-XChange, Chrome and
  Firefox must each be opened against the same file, and the result recorded.
  Budget a phase, not an afternoon.
- **Phase 3 can strand schema 26 in the wild.** If 0.28.0 ships phase 3 without
  phase 4, the format must still be correct on its own. The migration test for
  the previous schema is the proof, not the intent.
- **An a11y gate that is too strict gets disabled.** Start with the shell and the
  dialogs, where the contract is stable, and add canvas rules only when the
  canvas has an accessible model worth asserting.
- **The macOS runner may queue again.** If GitHub's pool starves, the phase stays
  open rather than being marked done on a compile-only check.

## Verification

The local gate for every phase is the one in `AGENTS.md`. The release candidate
adds:

- `npm run test:robustness` and the focused migration tests for phases 3–4, plus
  a schema 26 fixture round-trip and a schema 1–27 corpus run.
- `npm run test:canvas`, `npm run test:import` and the focused UI suite for
  phases 1–2; a real optional-content export opened in all four readers.
- `npm run test:visual` and a fresh `npm run docs:capture` once the surfaces stop
  changing.
- `npm run bench:large` recorded against the budgets in `docs/limitations.md`,
  before and after phases 3–4.
- `cargo test --manifest-path src-tauri/Cargo.toml --lib` and `cargo fmt
  --check` for the cache file operation.
- `GRIDSCALR_DOCS_STRICT=1 npm run check:docs` and `npm run site:check` for the
  release metadata.
- A full `Release build` matrix, with the macOS artifact verified on real
  hardware before 1.0.0 is declared.

## Exit

0.28.0 is done when every phase issue is closed, the epic checklist is complete,
the gates above are green on the released SHA, and the release notes record the
schema 27 change, the OCG serialization change, the new a11y and performance
gates, the macOS artifact verification and the disposition of the `glib`
advisory.

The release must also leave the project in a state where **1.0.0 is a tag, not a
project**: schema frozen and documented, every artifact verified on its own
platform, no open P0/P1 bug, no unaccepted dependency alert, and every 1.0
release-gate item either met or explicitly deferred with a reason.
