## Phase 2 — import preflight relink from the picker (F-096)

- **Issue:** [#237](https://github.com/MajorJohnDoe/gridscalr/issues/237)
- **Branch:** `fix/237-preflight-relink`
- **Commit:** `0098d9e` (implementation and docs); handover commit follows on the same branch
- **Status:** PR open, awaiting conductor review

### Completed work

- Decision: **the picker allows the selection.** A page whose referenced PDF is
  missing stays selectable and is marked **File missing** with no preview and no
  thumbnail request; the file is deferred to the preflight. A TIF without its
  embedded PDF keeps the disabled state because it has no relink path.
- `projectImportDialog()` treats a missing PDF as selectable (`group.canLocate`),
  keeps thumbnails lazy, describes the tile with `aria-describedby`, selects it
  through **Select all**, and shows a note while a missing page is selected.
- `projectImportPreflightDialog()` adds a per-document skip state beside the
  existing changed-file confirmation and relink state. A missing source is
  neither relinked nor skipped silently: **Import pages** stays disabled and the
  summary names the pending document until **Relink…** or **Skip these pages**
  is used. **Do not skip** reverts it; a relink clears it.
- `summarizeImportPreflight()` takes an optional `acceptedSkips` set and reports
  `pendingMissingDocuments`; a pending missing source blocks the commit.
- `scripts/project-import-ui.mjs` recovers a moved PDF end to end through the
  picker and the preflight **Relink…** in the browser fallback, proves Cancel
  changes nothing, and asserts both project files stay byte-identical.
- User guide and workflows describe the new picker state and the relink-or-skip
  gate. F-096 is closed with the decision and its evidence.

### Decisions

- Selecting a missing page needs a recovery path to be honest, so only a
  relinkable document (a referenced PDF) is selectable. The skip button is
  offered only while another document still contributes an importable page;
  when every selected page is missing, relink and cancel are the only real
  outcomes and the summary says so.
- The skip is per document, explicit, reversible and in-memory, like the
  existing relink state. Nothing is written to either project before commit;
  the import stays one undo step and a structural checkpoint is unchanged.
- No schema change (stays 26), no new storage mode, no page-reference change.

## Phase 3 — schema 27 derived-PDF cache marker

### Decisions

- The migration adds **no** marker to an existing TIF. Inventing a converter
  version for bytes produced by an unknown earlier release would poison the key
  rule; absence of a marker is the honest state and embedded bytes stay.
- `embeddedPdf` and `derivedPdf` are mutually exclusive with embedded bytes
  winning, so a hand-edited file cannot make rendering depend on a cache.
- A stale or malformed marker never blocks a save: it is a rebuild, not lost
  data. Only a TIF with no derived source at all is an error.
- No rendering, export, import or package change; no auto-deletion; no source
  write; CCITT G3/G4 passthrough untouched.

## Phase 4 — derived-PDF cache lifecycle

- **Issue:** [#256](https://github.com/MajorJohnDoe/gridscalr/issues/256) (phase 4 of 4)
- **Branch:** `feat/256-derived-pdf-cache`
- **Schema:** stays 27
- **Status:** PR open, awaiting conductor review

### Completed work

- **Cache location and key.** A derived PDF lives in the sibling folder
  `<project stem>.derived/` with the key in the file name
  (`<sha256 first 16>-v<converterVersion>-p<pageCount>.pdf`). The folder is
  derived in Rust from the project path, so a cache can only be written beside
  its own project. `src-tauri/src/derived_cache.rs` decodes, size-caps, verifies
  as a PDF, writes through a flushed temporary sibling, re-hashes the final file
  and refuses a protected source path or a symlinked folder.
- **Lifecycle.** `src/features/derivedPdfCache/` builds on import into a saved
  project and on save for an embedded document whose scan is reachable, stores
  the `derivedPdf` marker, reuses a current cache on open, rebuilds silently on a
  missing or stale key, and refuses a scan whose SHA-256 does not match. A
  converter-version-only mismatch still opens a present cache when the scan is
  gone, because the drawing revision is unchanged.
- **Missing scan.** One localized dialog names the document and the expected
  path and offers **Locate the scan…**; a located TIF is checksum-validated and
  rebuilt. The project is not opened on a blank page, and a TIF marker document
  no longer falls through to the PDF picker (which used to change its kind).
- **Passthrough.** `TiffConversion.passthrough` and
  `DocumentSourceInfo.passthrough` record a document whose every page kept its
  compressed strips (CCITT G3/G4 or JPEG-in-TIFF). It stays embedded, never
  acquires a cache entry, and the CCITT per-strip bytes are untouched.
- **Rendering paths.** The main loader, the reference pane and revision
  comparison, and the project import source all resolve a marker through the
  same `loadDerivedPdfBytes()`. The import picker marks a TIF available when its
  cache exists or its scan can rebuild it (F-113).
- **Packages.** A cache-backed scan ships its derived cache under `derived/`
  and its original scan is never included; an embedded scan may still include
  its scan under `source-scans/`. The manifest gains `derivedCaches` with
  `kind: "derived"` (Rust + TS), the README states the rule, extraction and
  inspection accept the section, and the packaged project rewrites
  `derivedPdf.relativePath` to the archive path.
- **Enforced budget.** `evaluateDerivedCacheBudget()` warns once per changed
  state at 160 MiB of derived cache or when JSON plus cache approaches the
  256 MB project limit; the save is never blocked. Measured reference project (6
  × A2-class colour sheets, 4960 × 3508 at 300 DPI): **79.19 MiB embedded JSON →
  0.01 MiB cached JSON**, with 59.39 MiB of cache on disk
  (`GRIDSCALR_DERIVED_BENCH=1 npx vitest run tests/derivedPdfBudget.test.ts`).
- **Docs.** ADR 0015 moved from deferred to implemented with the failure-mode
  table and the measurement; `docs/limitations.md`, `docs/user-guide.md`,
  `docs/project-file.md`, `docs/architecture.md`, `AGENTS.md` and `README.md`
  updated.

### Decisions

- A cache is only written from bytes the current converter produced. An embedded
  document is converted again from its scan at save time rather than stamping
  the current converter version on bytes an older release produced (keeps the
  phase 3 rule honest). If the scan is unreachable, the bytes stay embedded.
- The cache folder is `<project stem>.derived/`, not `<project stem>.drawings/`,
  so the managed-copy inventory and its **Remove unused drawings…** action never
  see a cache, and no cache is deleted automatically.
- A converter-version-only mismatch opens a present cache when the scan is gone;
  any source-hash or page-count mismatch is a rebuild, never trust.
- The budget is a warning, not a refusal; the 256 MB project limit stays the
  only hard stop.
- No schema bump (stays 27), no new source storage mode, no source write.
