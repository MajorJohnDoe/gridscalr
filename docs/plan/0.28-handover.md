## Phase 2 — import preflight relink from the picker (F-096)

- **Issue:** [#237](https://github.com/MajorJohnDoe/gridscalr/issues/237)
- **Branch:** `fix/237-preflight-relink`
- **Commit:** `0098d9e` (implementation and docs); handover commit follows on the same branch
- **Status:** PR open, awaiting conductor review

### Completed work

- Decision: **the picker allows the selection.** A page whose referenced PDF is
  missing stays selectable and is marked **File missing** with no preview and no
  thumbnail request; the file is deferred to the preflight. A TIF without its
  embedded PDF keeps the disabled state because it has no relink path.
- `projectImportDialog()` treats a missing PDF as selectable (`group.canLocate`),
  keeps thumbnails lazy, describes the tile with `aria-describedby`, selects it
  through **Select all**, and shows a note while a missing page is selected.
- `projectImportPreflightDialog()` adds a per-document skip state beside the
  existing changed-file confirmation and relink state. A missing source is
  neither relinked nor skipped silently: **Import pages** stays disabled and the
  summary names the pending document until **Relink…** or **Skip these pages**
  is used. **Do not skip** reverts it; a relink clears it.
- `summarizeImportPreflight()` takes an optional `acceptedSkips` set and reports
  `pendingMissingDocuments`; a pending missing source blocks the commit.
- `scripts/project-import-ui.mjs` recovers a moved PDF end to end through the
  picker and the preflight **Relink…** in the browser fallback, proves Cancel
  changes nothing, and asserts both project files stay byte-identical.
- User guide and workflows describe the new picker state and the relink-or-skip
  gate. F-096 is closed with the decision and its evidence.

### Modules

- `src/features/projectImport/ui.ts`, `preflightUi.ts`, `relink.ts`
- `src/styles/projectImport.css`
- `src/i18n/locales/{en,sv}.json`, `src/i18n/types.generated.ts`
- `tests/projectImportUi.test.ts`, `tests/projectImportPreflightUi.test.ts`,
  `tests/projectImportRelink.test.ts`, `scripts/project-import-ui.mjs`
- `docs/user-guide.md`, `docs/workflows.md`,
  `docs/plan/foundation-findings.md`

### Decisions

- Selecting a missing page needs a recovery path to be honest, so only a
  relinkable document (a referenced PDF) is selectable. The skip button is
  offered only while another document still contributes an importable page;
  when every selected page is missing, relink and cancel are the only real
  outcomes and the summary says so.
- The skip is per document, explicit, reversible and in-memory, like the
  existing relink state. Nothing is written to either project before commit;
  the import stays one undo step and a structural checkpoint is unchanged.
- No schema change (stays 26), no new storage mode, no page-reference change.

### Findings

- F-096 closed as fixed.
- F-113 recorded (P3, deferred): a TIF whose embedded PDF is missing has no
  picker or preflight recovery path; phase 3/4 decides it together with the
  derived-PDF cache.

## Phase 3 — schema 27 derived-PDF cache marker

- **Issue:** [#256](https://github.com/MajorJohnDoe/gridscalr/issues/256) (phase 3 of 4)
- **PR:** [#264](https://github.com/MajorJohnDoe/gridscalr/pull/264)
- **Branch:** `feat/256-schema-27`
- **Commit:** `6c57efe` (implementation and docs); handover commit follows on the same branch
- **Schema:** 26 → 27
- **Status:** PR open, awaiting conductor review

### Completed work

- `SCHEMA_VERSION` is 27 exactly once. `DocumentRef.embeddedPdf` is optional for
  a TIF document, and `DocumentRef.derivedPdf` is the explicit cache marker:
  `sourceSha256`, `converterVersion`, `pageCount` and a project-relative
  `relativePath`.
- `src/model/derivedPdf.ts` holds `DERIVED_PDF_CONVERTER_VERSION = 1`, the pure
  key rule (`derivedPdfCacheIsCurrent`: source hash, converter version and page
  count must all match) and the marker shape check (64-hex hash, integer version
  and page count, project-relative path with no drive prefix or `.`/`..`).
- `src/io/projectFile/derivedPdf.ts` normalizes the marker, runs the schema
  26 → 27 migration and asserts that a TIF names exactly one derived-PDF form.
  `normalizeDocument()` reads the marker, keeps embedded bytes as the shipped
  form, and reports a marker that sits beside embedded bytes.
- Migration adds nothing: every schema 26 TIF keeps its `embeddedPdf` byte for
  byte and renders as today. A marker in pre-27 data is ignored and counted as
  `repairedDerivedPdf`. A malformed marker is dropped as `droppedDerivedPdf` and
  the document is kept. A TIF with neither form keeps the previous hard error.
- `validateProject()` reports `tiffDocumentWithoutDerivedPdf` (error),
  `invalidDerivedPdfCache` and `derivedPdfCacheStale` (warnings), with localized
  text in `en.json`/`sv.json`. Nothing is silently dropped or remapped.
- `fixtures/legacy/schema-27.gridscalr` added (cache-backed TIF); the corpus now
  covers 1–27. `schema-26.gridscalr` is the previous-schema fixture.
- Docs: `docs/project-file.md` (format, marker example, validation list),
  `README.md`, `AGENTS.md` (schema line, corpus range, architecture map), ADR
  0015 implementation status, `docs/architecture.md`, `docs/testing.md`,
  `docs/roadmap.md`, `docs/limitations.md`, the user-guide format section and the
  `docs/plan/0.28.md` status line.

### Modules

- `src/model/derivedPdf.ts` (new), `src/model/types.ts`,
  `src/model/integrity.ts`
- `src/io/projectFile/derivedPdf.ts` (new), `documents.ts`, `parse.ts`
- `tests/derivedPdf.test.ts` (new), `tests/robustness/migrations.test.ts`,
  `tests/layerHierarchyMigration.test.ts`, `tests/projectFile.test.ts`
- `scripts/make-legacy-fixtures.mjs`, `fixtures/legacy/schema-27.gridscalr`
- `src/i18n/locales/{en,sv}.json`, `src/i18n/types.generated.ts`
- `docs/project-file.md`, `README.md`, `AGENTS.md`, `docs/adr/0015-…`,
  `docs/architecture.md`, `docs/testing.md`, `docs/roadmap.md`,
  `docs/limitations.md`, `docs/user-guide.md`, `docs/plan/0.28.md`

### Decisions

- The migration adds **no** marker to an existing TIF. Inventing a converter
  version for bytes produced by an unknown earlier release would poison the key
  rule; absence of a marker is the honest state and embedded bytes stay.
- `embeddedPdf` and `derivedPdf` are mutually exclusive with embedded bytes
  winning, so a hand-edited file cannot make rendering depend on a cache.
- A stale or malformed marker never blocks a save: it is a rebuild, not lost
  data. Only a TIF with no derived source at all is an error.
- No rendering, export, import or package change; no auto-deletion; no source
  write; CCITT G3/G4 passthrough untouched.
