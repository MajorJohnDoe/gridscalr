## Decisions

- The run is time-boxed: no new phase starts with fewer than 45 minutes left of
  the 90-minute budget. A phase in flight at the limit is pushed and its PR is
  left open for the next run rather than merged unverified.
- Phases run one at a time because a worker checks its branch out in the shared
  `/workspace` checkout. Conductor commits happen in
  `/tmp/opencode/conduct` on `main`.
- Phase 10 is the only schema change (25 → 26). Any phase that changes
  `SCHEMA_VERSION` without the full schema gate is a stop condition.
- Phase 12 ([#58](https://github.com/MajorJohnDoe/gridscalr/issues/58)) does not
  change the schema.
- No version bump, tag or release: 0.25.0 is not approved for release.

## Verification loop

The two-tier rule in `AGENTS.md` applies:

- the **local gate** is the guard scripts, `format:check`, `lint`,
  `check:i18n`, `check:themes`, `npx tsc --noEmit` and the focused Vitest files,
  targeting under two minutes;
- **CI is authoritative** and runs the whole list on the PR head;
- heavyweight local suites run only when the change touches their area —
  `tests/robustness/` for page/save/source work, `cargo fmt/check/test --lib`
  for Rust, `test:visual` and the matching browser suite for rendered changes,
  `docs:capture` when a captured screen changed, `tauri build -- --no-bundle`
  once before the push for shell changes.

Nothing merges until its own PR and the `main` commit it is based on are green.
Attempt budget per worker: three fix → push cycles. Environment failures are
re-run once and recorded, never fixed by changing application code.

### Phase 1 — [#182](https://github.com/MajorJohnDoe/gridscalr/issues/182) Polish page drag-and-drop

- **Branch:** `feat/182-page-drag-drop`, cut from `origin/main` at `5425a9c`.
- **PR:** [#215](https://github.com/MajorJohnDoe/gridscalr/pull/215), code commit
  `b3d1958` plus this handover commit.
- **Status:** merged as `9f78c82` after all six CI checks passed on
  `d5a8ce4`; focused `pageReorder` and page-identity tests re-run by the
  conductor on that exact SHA.
- **Completed:** a drop line between cards instead of a card outline; auto-scroll
  near the panel edges; multi-page selection with `Ctrl/Cmd` and `Shift` click and
  drag of the whole selection; `Alt+Up/Down` and `Alt+Home/End` reorder with a
  polite live-region announcement and focus recovery; document run headers when a
  project has more than one source; a cross-document drop line labelled with the
  target document; one structural checkpoint per drop; one shared insertion-index
  model so mouse and keyboard produce the same order.
- **Modules:** `src/features/pageReorder/` (`index.ts`, `model.ts`,
  `controller.ts`, `ui.ts`) is the new foundation feature and is registered in
  `scripts/check-module-boundaries.mjs`. Shared pure ordering lives in
  `src/model/pages.ts` (`pageListAfterMove`, `pageListOrderChanges`);
  `src/features/pageModel` gains `movePages` and the `reorderPages` action;
  `state/store.ts` gains `reorderPages`; `src/ui/pageList.ts` is wiring only.
- **Decisions:** the drop indicator is an insertion index, not a card class, and
  the same index drives the keyboard move. A drop that changes nothing writes no
  checkpoint. Page selection is session-only UI state in the controller; the store
  keeps the page order only. `.is-selected` renders only for a multi-selection so
  a single click does not add a second active look. `pageList` remains the single
  widget; no second page list was added.
- **Files:** `src/ui/pageList.ts` (+3 lines net), `src/styles/pageModel.css`,
  `src/i18n/locales/en.json`, `src/i18n/locales/sv.json`, `tests/pageReorder.test.ts`,
  `tests/viewOnly.test.ts`, `file-budgets.json` (two existing legacy budgets
  raised through `--update`), `docs/shortcuts.md`, `docs/user-guide.md`,
  `docs/plan/foundation-findings.md`.
- **Findings:** F-075 — the Pages panel renders at most 400 cards, so pages past
  the cap cannot be selected or reordered.
- **Checks:** local gate green (`check:versions`, `check:file-budgets`,
  `check:modules`, `check:security`, `check:dependencies`, `check:docs`,
