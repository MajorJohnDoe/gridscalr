## Decisions

- The run is time-boxed: no new phase starts with fewer than 45 minutes left of
  the 90-minute budget. A phase in flight at the limit is pushed and its PR is
  left open for the next run rather than merged unverified.
- Phases run one at a time because a worker checks its branch out in the shared
  `/workspace` checkout. Conductor commits happen in
  `/tmp/opencode/conduct` on `main`.
- Phase 10 is the only schema change (25 → 26). Any phase that changes
  `SCHEMA_VERSION` without the full schema gate is a stop condition.
- Phase 12 ([#58](https://github.com/MajorJohnDoe/gridscalr/issues/58)) does not
  change the schema.
- No version bump, tag or release: 0.25.0 is not approved for release.

## Verification loop

The two-tier rule in `AGENTS.md` applies:

- the **local gate** is the guard scripts, `format:check`, `lint`,
  `check:i18n`, `check:themes`, `npx tsc --noEmit` and the focused Vitest files,
  targeting under two minutes;
- **CI is authoritative** and runs the whole list on the PR head;
- heavyweight local suites run only when the change touches their area —
  `tests/robustness/` for page/save/source work, `cargo fmt/check/test --lib`
  for Rust, `test:visual` and the matching browser suite for rendered changes,
  `docs:capture` when a captured screen changed, `tauri build -- --no-bundle`
  once before the push for shell changes.

Nothing merges until its own PR and the `main` commit it is based on are green.
Attempt budget per worker: three fix → push cycles. Environment failures are
re-run once and recorded, never fixed by changing application code.

### Phase 3 — [#184](https://github.com/MajorJohnDoe/gridscalr/issues/184) Undoable page reorder and insert

- **Branch:** `feat/184-undoable-page-edits`, cut from `origin/main` at `cacf7af`.
- **PR:** [#217](https://github.com/MajorJohnDoe/gridscalr/pull/217), code commit
  `728d737` plus this handover commit.
- **Status:** merged as `e2320bd` after all six CI checks passed on
  `caac930`; `tests/pageHistory.test.ts`, `tests/pageReorder.test.ts` and the
  whole `tests/robustness/` suite re-run by the conductor on that exact SHA.
- **Completed:** one drag and one insert are each exactly one undo step, with the
  same `PageId` order and every page's `state` restored by undo and redo. A drop
  that changes nothing pushes no history entry. Delete, duplicate, document
  import and source replacement keep clearing history and writing a checkpoint,
  and a reorder or insert still writes its checkpoint before it runs. The visible
  page now follows its `PageId` through undo and redo, and the renderer display
  order is reapplied only when its signature changed, so the canvas, thumbnails
  and page sizes follow a restored page list.
- **Modules:** no new feature directory. History semantics stay in
  `src/state/store.ts` (`mutatePageList`, `afterHistoryRestore`), the order
  signature is `pageOrderSignature` in `src/model/pages.ts`, the renderer tracks
  `appliedPageOrder` in `src/pdf/pdfRenderer.ts`, and
  `src/app/rendererDocuments.ts` gains `syncPageOrder`, reused by `reconcile`.
  `src/features/pageModel/appActions.ts` exports `insertProjectPage` and
  `reorderProjectPage` directly. `App.ts` is unchanged.
- **Decisions:** duplicate stays an explicit, non-undoable boundary in 0.25.0
  because it copies items, scale and name and can clone a template sheet
  document; making it undoable needs its own invariant tests (ADR 0011). The
  visible page follows its `PageId` while it exists, then the display position is
  clamped. Undoability does not replace the recovery checkpoint. A whole
  multi-page drag is still one step. `file-budgets.json` raises the existing
  `src/state/store.ts` legacy budget (960 → 993); no new exception.
- **Files:** `src/state/store.ts`, `src/model/pages.ts`, `src/pdf/pdfRenderer.ts`,
