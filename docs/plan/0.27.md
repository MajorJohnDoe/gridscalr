# 0.27.0 — limits, lifecycle and tooling safety

**Status:** planned 2026-11-12. No phase started. Phases 8–10 were added on
2026-11-13 from the post-0.26.0 focus bug and the theme-blind Layers surface.
**Baseline:** 0.26.0, project-file schema 26.
**Epic:** [#242](https://github.com/MajorJohnDoe/gridscalr/issues/242).
**Milestone:** `0.27.0`.
**Handover:** `docs/plan/0.27-handover.md` (create with the first phase).

0.27.0 is a foundation release. It closes the write paths that can still accept
more bytes than the app can safely read, makes managed copies removable without
guessing, and finishes the security and tooling gates that still depend on a
manual check. There is **no schema change** and no new drawing feature.

The release follows the conductor workflow in
[`conductor-prompt.md`](conductor-prompt.md): one fresh worker per phase, one
pull request per phase, defensive review against the PR head SHA, and a handover
update after every merge.

## Why now

- The 0.24.0 security audit left follow-ups that are cheap to close and expensive
  to leave open: Windows path coverage, pinned actions and untested output caps.
- The managed drawings folder has no explicit cleanup, and source replacement can
  leave a stale managed file and stale provenance.
- The docs, screenshot and Rust module-boundary gates still have known gaps
  (F-097, F-098, F-100, F-101). A release pass is the right time to close them.
- The colour-scan and page-scoped OCG decisions are documented trade-offs that
  need one owner and a written answer before 1.0.
- A user-visible focus bug remains after 0.26.0: the 30 s source check emits a
  synthetic save, the shell re-renders and the field being typed in is replaced.
  The autosave focus fix does not cover it.
- The Layers and Mätlager section surfaces bypass the theme contract: a
  hard-coded grey keeps the lists dark in the light theme.

## Decisions and non-goals

- **No schema change.** Template sheet fields stay on the document (F-011);
  moving them to the page is a separate schema 27 decision, not part of 0.27.0.
- **No automatic deletion.** A managed file is removed only by the explicit
  cleanup action or by replacing its source, and only after a fresh reference
  check.
- **Fixed managed folder.** `<project>.drawings/` stays fixed (F-014); a
  project-level folder preference is not planned.
- **No new storage mode.** Reference and managed copy remain the two modes;
  packages remain transport.
- **Bulk page actions and the 400-card cap stay in #234.** They are a page
  workspace follow-up, not a release gate.
- **TIF policy is a decision first.** If #238 decides on a different colour-scan
  storage, the implementation gets its own issue and does not ride along.
- **The shell keeps render-from-state.** Phase 8 adds focus preservation,
  deferral and render coalescing; it does not introduce a framework, a virtual
  DOM or per-field reconciliation.
- **A source check never changes the project.** Phase 9 removes the synthetic
  store event and keeps the status chips and page badges as the only consumers of
  the source summary; no new store reason or event bus.
- **No palette redesign.** Phase 10 moves two component surfaces into the token
  contract; it does not restyle the palette, and medium grey keeps its literal
  values so the default look is unchanged.

## Risks

- **Package free-space checks can be wrong on a network share.** Report the
  failure explicitly and keep the existing temporary-file cleanup; do not
  silently lower the cap.
- **Trash/move semantics differ by platform.** Prefer a reversible move and
  report the final path; never claim a file is recoverable when it is not.
- **Pinned actions can go stale.** Dependabot must update the pins; a pin without
  a version comment is a review finding.
- **A Windows-only path test can be skipped by the filesystem.** Assert the
  skip reason and keep at least one real junction or verbatim-prefix case.
- **The TIF decision may be larger than a phase.** If it needs a schema or a
  storage-mode change, stop and cut a follow-up issue rather than expanding
  0.27.0.
- **Focus restoration can target the wrong control.** Match the captured field by
  tag, type, id or role and skip the restore when the structure no longer
  matches; never steal focus from a control the user moved to.
- **A deferred background render can delay a source warning.** That is accepted:
  the chips and badges update when the user leaves the field, and no warning is
  lost.

## Verification

The local gate for every phase is the one in `AGENTS.md`. The release candidate
adds:

- `npm run test:ui`, `npm run test:csp` and the focused UI suite for a changed
  panel; `npm run test:canvas` for phases 8–9 and a rendered Light Green /
  Medium Grey Layers check for phase 10.
- `npm test -- --run` and `npm run test:robustness`.
- `cargo test --manifest-path src-tauri/Cargo.toml --lib`, with the Windows job
  running the save and package modules after phase 4.
- `GRIDSCALR_DOCS_STRICT=1 npm run check:docs` and a fresh `npm run docs:capture`.
- `npm run site:build` and `npm run site:check` after the release metadata
  update.
- A tagged build on Windows, macOS and Linux before the GitHub Release is
  published.

## Exit

0.27.0 is done when every phase issue is closed, the epic checklist is complete,
the gates above are green on the released SHA, and the release notes record the
new caps, the cleanup action, the pinned-action policy and the TIF/OCG decision.
The release must also show that typing in a panel field survives the 30 s source
check and that the source monitor no longer emits a store event. The Layers and
Mätlager surfaces must follow every palette while Medium Grey stays unchanged.
