## Phase A — keep the straight-line guide when drawing to the I/O rail

- Issue: #377
- PR: #380
- Commit: `6b10e6c` (squash `f829e98`)
- Schema: unchanged

### Completed

- Added pure `snapAlongAxis()` and a shared `orthoPoint()` in `src/model/snap.ts`.
- `CanvasView.constrainPolyline()` tries the axis-preserving target before the
  any-angle snap, sets the snap indicator to the projected candidate and keeps
  the plain ortho result when no target is on the guide.
- Polyline creation and preview pass the raw pointer so the axis is chosen from
  the pointer, not from an already-projected snap point.
- Rail rows are covered as segment candidates; the pointer can project anywhere
  along a row.
- Tests cover vertical and horizontal row landings, off-axis port fallback, no
  target, zoom tolerance and the rail-row segment candidate.

### Modules

- `src/model/snap.ts`
- `src/canvas/CanvasView.ts`
- `src/canvas/pointer/creation.ts`
- `tests/snap.test.ts`

### Decisions

- Axis targets are preferred only when the candidate is on or near the guide.
  An off-axis port keeps today's any-angle snap instead of being projected onto
  a distant axis.
- No schema, version or dependency change.

### Checks

- Local gate, `tests/snap.test.ts`, full Vitest suite and `test:canvas` passed.
- CI green on PR head `6b10e6c`.
