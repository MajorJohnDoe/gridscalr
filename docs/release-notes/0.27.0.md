# GridScalr 0.27.0

This release closes the write paths that could still accept more bytes than the
app can safely read, gives unreferenced managed drawings an explicit removal
action, and finishes the security and tooling gates that still depended on a
manual check. It also fixes a focus loss that replaced the field you were typing
in, stops a source check from looking like a project change, and makes the Layers
and Mätlager surfaces follow every palette. There is no schema change and no new
drawing feature.

The project-file schema stays **26**. No migration is needed.

## Download

Windows portable, NSIS and MSI builds, one universal macOS DMG and app zip, and
Linux AppImage, deb and tarball are published on the GitHub Release for
`v0.27.0`, together with `SHA256SUMS.txt`. The builds are unsigned; see
**Install** in the README.

## Write limits and cleanup

- **Package creation checks before it writes.** A package is refused when its
  uncompressed content exceeds the documented 2 GiB cap or when the destination
  volume cannot hold the content plus a 64 MiB reserve. The check runs before the
  temporary file or folder exists, so a refused package leaves nothing behind.
  The message states the required size and the cap, in the app language.
- **The package dialog shows the size.** It reports the expected uncompressed
  size and recomputes it when the optional exports change, and a
  known-too-large package is refused before you are asked for a path. The
  estimate covers the known content; the final total is still checked in the
  desktop shell, so a large optional export can be refused after the dialog
  instead of being written.
- **Managed copies use the same source cap.** **Use managed copy**, **Copy into
  project** and **Consolidate drawings…** apply the 1 GiB per-file source limit
  before hashing or streaming, so an oversized pick is refused before the
  drawings folder is created.
- **Stale temporary files are cleaned up.** After a successful project load,
  GridScalr removes stale save siblings next to the project and stale
  package-extraction folders (`.extract-<pid>-<stamp>`) in the same folder.
  A temporary file that a live process still owns is left alone, and a
  `.previous-` folder that holds a replaced version is never removed.
- The free-space probe is best-effort on a network share. When the volume cannot
  report free space, the explicit byte cap stays the only limit.
- Fixed: the extraction free-space dialog always showed `0` and `0` because the
  size fields were serialized in the wrong case.

## Remove unused drawings

- **One explicit action.** The project doctor's **Sources** section lists every
  file in `<project>.drawings/` that no document references, with its size and
  the total. Select the copies and choose **Remove unused drawings…**; you review
  the full list and count before confirming.
- **Re-checked immediately before removal.** The doctor re-lists the folder and
  rebuilds the reference set from the open project at that moment, so a copy that
  is still referenced, or became referenced while the dialog was open, is skipped
  and counted in the report.
- **Nothing is hard-deleted.** A removed file goes to the operating system trash
  when that is available. Otherwise the batch is moved into one timestamped
  `.<project>.<pid>.<stamp>.<counter>.removed` folder beside the project, and the
  doctor reports that path so you can restore or delete it yourself. A
  `.removed` folder is never removed automatically.
- The action is disabled for a read-only project and when the folder holds no
  unused copy. It is the only path that removes a managed file; a save, a source
  change and a timer never do.
- Windows and macOS use the platform trash backend; Linux follows the desktop
  trash specification. Silently unavailable trash is reported as the fallback
  folder.

## Source replacement

- **A managed PDF stays managed.** Replacing a managed copy with **Replace
  source…** copies the new pick into `<project>.drawings/` and verifies its
  SHA-256 before any project field changes. The document keeps managed mode and
  its recorded original path and checksum describe the new pick.
- A failed copy or a checksum mismatch cancels the replacement; the old document
  and its file are untouched, and the project is not half-applied.
- **The previous copy is left for the doctor.** It becomes an unreferenced file
  that **Remove unused drawings…** lists. The referenced new copy is protected by
  its resolved path, so no spelling or link can remove it.
- A replacement that ends as a reference clears the replaced managed provenance
  instead of inheriting it, so the saved project no longer carries a stale
  absolute path.
- A split replacement, where only some pages map, still copies the new pick. A
  TIF replacement stays a reference because its derived PDF lives inside the
  project.

## Windows path coverage and a write-guard fix

- **The Rust path, save and package tests run on all three platforms.** The CI
  `desktop` job now runs `cargo test --lib` on Ubuntu, Windows and macOS, so the
  modules that encode platform file-system rules execute on the platform they
  describe.
- Added Windows cases for the verbatim `\\?\` prefix, a case-insensitive volume,
  a trailing-dot and trailing-space alias, drive-relative rejection, UNC
  spellings, and a real `mklink /J` junction.
- **Fixed (P2):** a `..` spelling behind a symlinked root could slip past the
  source write guard. The guard now normalises `.` and `..` before it asks the
  file system, then canonicalises, so `<dir>/other/../drawings/Plan.pdf` is
  recognised as the protected source even when the root is a link. A Unix test
  covers it.
- The guard can still only refuse a write, never allow one. A `.lock-tmp` or
  `.deleted` suffix family outside the project folder remains uncleaned and is
  documented as a limit.

## Security and tooling gates

- **Every GitHub Action is pinned to a commit.** All 35 remote `uses:` references
  in `ci.yml`, `pages.yml`, `release.yml` and `docs-capture.yml` are full
  40-character commit SHAs with the release in a trailing comment. Each SHA was
  resolved from the action's tag through the GitHub API and verified as contained
  in the action's default branch. `dtolnay/rust-toolchain` publishes no
  per-release tags, so it is pinned to a `master` commit with `toolchain: stable`
  named explicitly.
- **`npm run check:actions`** fails on a tag, a branch, a short SHA, a missing
  version comment, a container without a digest, or one action release pinned to
  two different SHAs. The pin-bump procedure, including the annotated-tag and
  default-branch checks, is in `docs/releasing.md`.
- **Shortcut tables are pinned.** `check:docs` now compares both README tables
  and the eight tables in `docs/shortcuts.md` with a catalogue of 97 documented
  rows, so a renamed binding, a changed row or a stale quoted code fails the
  check instead of shipping a wrong shortcut.
- **The screenshot capture has a dry run.** `npm run test:docs-capture` runs the
  same steps and locators into a temporary folder and never rewrites
  `docs/screenshots/`, and a workflow runs it weekly, on demand and on a pull
  request labelled `docs-capture`.
- **Rust module boundaries are enforced by a command cap.** `rust-commands.json`
  caps Tauri commands per module (default 2, nine reviewed exceptions), and
  `check:modules` also fails a `.rs` file that no other module declares, so a
  command cannot be parked in an already large module.
- `src/features/schematics` has a public `index.ts` like every other foundation
  feature; 24 files now import only that surface.

## Editing and status

- **Typing survives a background check.** A shell render requested while an
  editable field has focus is deferred until that field loses focus, and an
  immediate render restores focus, value, caret and the nearest scroll position.
  Typing in Properties, Layers or Pages is no longer interrupted by the 30 s
  source check, and `Enter` and `Tab` keep working. A control you moved to is
  never displaced, and a value is only written back when the rebuilt field is
  matched by `id` or `data-role`.
- **A source check is no longer a project change.** The source monitor compares
  the completed status set and notifies only when a document's state or storage
  mode changed. An unchanged poll causes no store event, no notification and no
  render; a changed, missing or closed source still does. The status-bar chips
  and the Pages badges refresh without rebuilding the panel or dropping an open
  page-rename field.

## Themes

- The Layers and Mätlager section rows and footer now use the `--surface-inset`
  and `--surface-inset-foot` tokens instead of a hard-coded grey, so the lists
  follow the palette in Light Green and in System-light and System-dark.
- **Medium Grey is unchanged.** The default theme keeps its previous literal
  values, and the four visual baselines stayed at 0 differing pixels.
- `check:themes` requires both tokens in every palette, and the UI smoke test
  asserts the rendered surfaces and row-name contrast in all seven theme states.

## Decided limits and planned follow-ups

- **Colour-scan TIF storage stays embedded for now** (ADR
  [0015](../adr/0015-colour-scan-storage.md)). The accepted operating budget is
  **8 MiB of project JSON per 25 MP colour page and 160 MiB of embedded derived
  PDFs per project** — about twenty 25 MP sheets, or eight A1 sheets at 300 DPI —
  against the 256 MB project limit. The 256 MiB decoded-raster guard, not the
  400 MP pixel cap, is what limits one colour page to about 89 MP, and its worst
  case is roughly 341 MiB of base64, so the project-size limit is the hard stop.
  A photographic set can reach it with two or three sheets; split a large colour
  set or save it as a separate project.
- The measured figures are in the ADR: a 25 MP RGB line-art sheet is 71.5 MiB
  decoded, 5.4 MiB Flate and 7.2 MiB of base64; an A1 at 300 DPI is 69.7 MP,
  199.4 MiB decoded, 15.1 MiB Flate and 20.1 MiB of base64; the same 25 MP sheet
  as 1-bit is 10 KiB.
- The target design is reference TIF plus a rebuildable derived-PDF cache keyed
  by the TIF checksum and converter version. It needs schema 27 and is **planned,
  not shipped**, in [#256](https://github.com/MajorJohnDoe/gridscalr/issues/256).
- **Drawing export keeps one optional-content group per layer** (ADR
  [0016](../adr/0016-optional-content-export-shape.md)), with per-page marked
  content inside it. That keeps the reader's layer list usable and expresses the
  schema 26 hierarchy, and the flattened export remains the deterministic
  default. Per-page groups are an accepted trade-off.
- The nested-layer list uses a heading dictionary, which is an Acrobat extension
  rather than the ISO array form. Fixing that changes how a group that owns items
  appears in every reader, so it is **planned, not shipped**, in
  [#257](https://github.com/MajorJohnDoe/gridscalr/issues/257), together with a
  naming rule for group content and verification in Acrobat and Firefox.
- CCITT G3/G4 TIF pages stay a byte-for-byte passthrough; a test now asserts that
  the derived PDF's fax streams equal the source strips exactly.

## Toolchain

- The Rust minimum supported version is now **1.87**, and `Cargo.lock` is format
  4. The new `trash` 5.3 dependency (MIT) provides the operating-system trash
  integration; it adds only `urlencoding` transitively.

## Known and accepted issues

- A managed-copy listing reads only regular `.pdf` files directly inside
  `<project>.drawings/`, one level deep. A subfolder you create yourself, a
  non-PDF file and a stale package-extraction folder are never listed or removed
  there; `.lock-tmp` and `.deleted` suffixes outside the project folder are not
  cleaned automatically.
- Workflow pins do not update themselves. There is no Dependabot rule for
  actions, and `actions/download-artifact` stays at its pinned major until a
  separate refresh is reviewed.
- A relocated `.removed` folder is reported once and never listed again, so it
  stays on disk until you delete it.
- A managed TIF, which the app cannot create, would degrade to a reference on
  replacement.
- The Pages list still renders at most 400 cards.

## Upgrade notes

- Schema 26 is unchanged from 0.26.0. Projects saved by 0.26.0 open directly.
- No file is moved by upgrading. A managed copy from 0.26.0 stays where it is and
  is listed as before.
- Building from source now needs Rust 1.87 or newer.
