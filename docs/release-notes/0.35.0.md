# GridScalr 0.35.0

Foundation follow-ups and page-workspace improvements. There is no schema change;
the project-file schema stays 28.

## Foundation follow-ups

- **Every feature directory now has the same 400-line budget.** A single
  `src/features: 400` rule replaces per-directory registration, so a feature
  directory added later is capped without being listed. The two packages and the
  import controller that exceeded it were split rather than excepted; the one
  reviewed exception that predates the rule remains
  ([#384](https://github.com/MajorJohnDoe/gridscalr/issues/384)).
- **One registry owns transient surfaces.** Tool flyouts, top menus and
  popovers register with a single stack, so their order is stable and `Esc`
  closes the topmost one before a dialog or the selection
  ([#383](https://github.com/MajorJohnDoe/gridscalr/issues/383)).
- **A schedule total with no visible column is still shown.** When a computed
  total has no renderable column — a hidden field, the label cell or a field
  already claimed by another total — it renders in the foot line instead of
  disappearing. The same foot line is drawn on the canvas, in the drawing PDF
  and in the dock table, and no total is recomputed
  ([#383](https://github.com/MajorJohnDoe/gridscalr/issues/383)).
- **A split-view pan reuses the reference pane's raster.** The read-only
  reference pane follows the primary gesture edge, so it blits its own raster
  while the split-view pan runs and settles with the primary instead of
  re-rendering. A debug tile probe now compares the tiled and whole-page base
  raster at zoom 1, 3 and 6 and records the verdict in the packaged smoke test on
  WebKitGTK, WKWebView and WebView2
  ([#385](https://github.com/MajorJohnDoe/gridscalr/issues/385)).

## Page workspace

- **Every page is reachable in a large project.** The Pages panel mounts a
  window of at most 120 filtered cards around the current page and adds a range
  bar with Previous, Next and a page-number jump. Reordering, drag-and-drop
  thumbnails and filters keep working inside the window
  ([#234](https://github.com/MajorJohnDoe/gridscalr/issues/234)).
- **Page commands follow the Pages selection.** Insert uses the first or last
  selected page; move, duplicate and delete use the whole selection. A bulk
  duplicate appends copies in project order as one undo step, and a bulk delete
  keeps the explicit, checkpointed page-delete boundary
  ([#234](https://github.com/MajorJohnDoe/gridscalr/issues/234)).
- **The Layers panel is an ARIA tree.** Each section exposes `tree`/`treeitem`
  roles, `aria-level`, `aria-expanded`, `aria-selected` and set positions, with a
  roving tab stop moved by ArrowUp/ArrowDown/Home/End. Row controls remain
  separate `Tab` stops ([#234](https://github.com/MajorJohnDoe/gridscalr/issues/234)).

## Dependency

- **`trash` 5.4.0 removes the compiled chrono path.** `trash` now uses `jiff`, so
  chrono is no longer compiled into the build graph. `chrono` remains only as an
  optional `serde_with`/`tauri-utils` lock entry, so the reviewed allowlist entry
  and its advisory stay until upstream drops the optional dependency
  ([#306](https://github.com/MajorJohnDoe/gridscalr/issues/306),
  [#390](https://github.com/MajorJohnDoe/gridscalr/issues/390)).

## Known issue

- **The tiled raster differs from the whole-page path on some platforms.**
  F-150 ([#389](https://github.com/MajorJohnDoe/gridscalr/issues/389)) covers the
  recorded differences on high-DPR WebView2 and WKWebView and at WebKit zoom 3.
  No blank tile and no material integer offset was found, so tiling stays
  enabled; the probe records the difference instead of hiding it.

## State

- No schema change; schema 28 is unchanged.
- Builds are unsigned and not notarized. Every platform artifact is published
  with one merged `SHA256SUMS.txt`.
- The macOS artifact is verified from the CI runner (universal binary, bundle
  identity, version and checksums). A physical macOS install — Gatekeeper
  acceptance, drag to Applications, Finder double-click and the `.gridscalr`
  association — remains unverified and is not claimed as hardware-tested.

## Verification baseline

- Accessibility: 7 palettes × 19 surfaces plus 5 Swedish checks (138 checks),
  0 serious or critical violations and 0 lower-impact findings reported.
- Touch targets: 757 visible controls across 23 surfaces, all at least 24 × 24
  CSS px with a coarse pointer.
- UI scale: 100 %, 150 % and 200 %, no overflow; the smallest canvas width was
  338 px at 200 %.
- Performance reference profile: 150 pages, 15 000 items, 60 images, 6.9 MB
  serialized project. p95 edit 70.7 ms, project open 37.3 ms, autosave 1.00 s,
  page switch 23.4 ms, UI freeze 217.5 ms. Serialization p95 30.7 ms, Markups
  open 217.5 ms with 15/15 060 rows rendered, and 67.5 MB browser JS heap.

## Verify

Open a project with more than 120 pages and use Previous, Next and the page
number jump; the current page is always in the mounted window. Select several
pages and duplicate them: the copies appear in project order and one Undo
removes the whole block. Select several pages and delete them: the confirmation
names the block, one recovery checkpoint is written and history is cleared.
Expand a layer group with the keyboard and move through the tree with the arrow
keys. Place a takeoff table with a hidden total column and confirm the total
appears in the foot line on the canvas, in the drawing PDF and in the dock
table. Pan in split view and confirm the reference pane keeps its image during
the pan.
