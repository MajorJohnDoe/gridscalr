# GridScalr 0.28.0

This is the **release candidate for 1.0.0**. It makes the last project-file
schema change before the 1.0 freeze, closes the two shipped interoperability bugs
that were still visible to a user, and turns the remaining manual release checks
into automated gates. There is no new drawing capability.

The project-file schema becomes **27**. Colour TIF scans are stored as a
reference with a rebuildable derived-PDF cache beside the project instead of
being base64-embedded in the project JSON. Older projects open through the
existing migration ladder; a schema 26 project is migrated deterministically and
renders exactly as before.

0.28.0 is not 1.0.0. It is the build that has to survive real-world use first:
1.0.0 follows only after this release has been tested on real drawings, real
project folders and the three published platforms.

## Download

Windows portable, NSIS and MSI builds, one universal macOS DMG and app zip, and
Linux AppImage, deb and tarball are published on the GitHub Release for
`v0.28.0`, together with `SHA256SUMS.txt`. The builds are unsigned; see
**Install** in the README. No physical macOS or Windows install was verified
before this release — see **Platform verification** below.

## Schema 27 — colour scans become a reference with a rebuildable cache

- **The project file no longer carries the raster twice.** A decoded colour or
  greyscale TIF page is converted to a derived PDF, and that PDF now lives in the
  sibling folder `<project>.derived/` beside the `.gridscalr` file. The project
  stores a `derivedPdf` marker instead of base64 bytes: the source scan's
  SHA-256, the converter version, the derived page count and the project-relative
  cache path. `DocumentRef.embeddedPdf` stays optional and an embedded PDF still
  wins if a hand-edited file somehow carries both forms.
- **The cache is a cache, never a source of truth.** It is built when a colour
  scan is imported into a saved project and when an embedded document is saved
  with a reachable scan. On open it is reused only while the source hash,
  converter version and page count all still match. A hash or page-count
  mismatch is a rebuild, never trust. Deleting the folder by hand costs a
  rebuild, never page content.
- **A missing scan has one explicit recovery path.** If the cache is missing and
  the original scan is still where the project expects it, the page is rebuilt
  silently. If both are gone, one dialog names the document and the expected path
  and offers **Locate the scan…**; a located TIF is checksum-validated and
  rebuilt. The project is not opened on a blank page, and a TIF marker document
  no longer falls through to the PDF picker and changes its kind.
- **The measured effect is large, on a colour set.** On a reference project of
  six A2-class colour sheets (4960 × 3508 px at 300 DPI), the project JSON fell
  from **79.19 MiB embedded to 0.01 MiB cached**, with **59.39 MiB** of cache on
  disk once (`GRIDSCALR_DERIVED_BENCH=1 npx vitest run
  tests/derivedPdfBudget.test.ts`). A different scan set will produce different
  numbers; a photographic set still costs more cache than a line drawing.
- **The budget is enforced as a warning.** GridScalr warns once per changed state
  when the derived cache reaches 160 MiB or when the project file plus its cache
  approaches the 256 MB project limit. The save is never blocked and no page is
  dropped to meet the budget. Split a large colour set into one project per
  building or floor.
- **CCITT G3/G4 passthrough is unchanged.** A 1-bit fax-compressed page keeps its
  source strips byte for byte, stays embedded, and never acquires a cache entry.
  JPEG-in-TIFF behaves the same way. A test asserts that the fax streams equal
  the source strips exactly.
- **Packages state which form they carry.** A cache-backed scan travels as its
  derived cache under `derived/` and its original scan is then never included;
  the manifest lists the section with `kind: "derived"`. An embedded scan may
  still include its original scan under `source-scans/` as before.
- **The migration adds nothing.** Every schema 26 TIF keeps its embedded PDF byte
  for byte, and every document, page, layer and item ID is preserved. A marker
  found in pre-27 data is ignored and counted in the load report. A TIF with
  neither form keeps the existing hard error instead of opening a page with no
  content. The committed corpus now covers schema 1–27, including a schema 27
  fixture and a schema 26 round trip.
- The project doctor reports `tiffDocumentWithoutDerivedPdf` as an error and
  `invalidDerivedPdfCache` or `derivedPdfCacheStale` as warnings. A stale marker
  never blocks a save: it is a rebuild, not lost data.
- **Save a copy stays project-only.** A `.gridscalr` copy keeps a marker that
  points at the original project's cache folder, so it rebuilds from the original
  scan when that is reachable and otherwise asks for it. **File → Share project
  package…** is the supported self-contained path.

## Optional layers nest in Firefox and pdf.js

- The optional-content export now writes the ISO 32000-1 Table 101 nested-array
  form (`[ (Folder) 12 0 R [ (Child) 13 0 R ] ]`) for `/Order` instead of the
  Acrobat heading dictionary. One optional-content group per visible exported
  layer, the same marked content and the same `/ON` state are unchanged; only the
  nesting shape changed.
- A group layer that also holds items repeats its layer name on a selectable
  entry inside its non-selectable folder, so its own items can still be toggled
  while its child layers keep their own entries. A group that only groups layers
  has no group of its own.
- The pdf.js worker nests the folders with no nameless fallback list, and the
  export opens and renders in Chromium. Chrome/PDFium exposes no layer panel to
  automation, so nesting is not asserted there. **Verification in Adobe Acrobat
  and PDF-XChange is still pending in
  [#257](https://github.com/MajorJohnDoe/gridscalr/issues/257)**; the shipped
  claim is the standard serialized form plus the pdf.js result, not a completed
  four-reader matrix.
- Exports written before 0.28.0 keep the heading-dictionary form and still list
  their groups flat in Firefox. They are released files, not project data, and
  are not rewritten.

## Import preflight relink from the picker

- A page whose referenced PDF is missing is now selectable in the project import
  picker and is marked **File missing** with no preview. The file is resolved in
  the import preflight with **Relink…** instead of forcing you to cancel the
  picker first.
- A missing source is never skipped silently: **Import pages** stays disabled
  until that document is relinked or you choose **Skip these pages**, which drops
  its selected pages explicitly and reversibly with **Do not skip**. The summary
  names the pending document. Cancel changes nothing in either project and both
  project files stay byte-identical.
- A TIF page is available when its derived PDF is embedded, its cache is present
  beside the project, or its original scan is reachable so the cache can be
  rebuilt. Opening a project, rather than the import picker, owns the one
  **Locate the scan…** recovery path for a TIF.

## Release gates in CI

- **Accessibility is a CI gate.** `npm run test:a11y` runs axe against the shell
  and the Project settings, Preferences, Quantities, Drawing export and Help
  dialogs in each of the five palettes — 30 palette × surface checks. Serious and
  critical violations fail with no allowlist. Baseline for this release: 30
  checks, 0 violations, one `color-contrast` incomplete per surface reviewed by
  hand.
- **Light Green contrast is fixed** (F-116,
  [#267](https://github.com/MajorJohnDoe/gridscalr/issues/267)). Seven text
  tokens were darkened to reach at least 4.88:1 on their darkest surface, and the
  status-bar layer colour is now a ringed swatch beside the layer name instead of
  coloured text (1.64:1 → 12.94:1). A new `--on-accent` token replaces the
  hard-coded near-black on primary buttons, so the accent pair stays correct in
  every palette.
- **Touch targets, UI scale and performance are CI gates.**
  `npm run test:touch-targets` measures every visible control under
  `(pointer: coarse)` — 365 controls across six surfaces, all at least
  24 × 24 CSS px. `npm run test:ui-scale` checks 100, 150 and 200 % as
  1920 × 1080, 1280 × 720 and 960 × 540 CSS px with the smallest canvas at
  338 px. `npm run check:performance` runs the 40-page, 4 000-item profile in CI
  and fails on a budget breach or a missing measurement; the reference profile is
  a release command. Reference profile at this release: p95 edit 71.8 ms, open
  29.3 ms, autosave 1.05 s, page switch 43.1 ms, Markups open 285.5 ms (UI freeze
  measured with the same row window), 6.4 MB serialized project. `docs/testing.md`
  adds the manual canvas and keyboard checklist.
- The **menu panel scrolls inside the window** at 200 % scale, which was a real
  unreachable-item bug the UI-scale gate found.

## Platform verification

- **The macOS artifact is checked automatically in CI.** The release job mounts
  the DMG, requires `GridScalr.app` with `Contents/MacOS/gridscalr`, proves the
  binary is universal with `lipo` (`x86_64` and `arm64`), matches
  `CFBundleShortVersionString` to the app version and `CFBundleIdentifier` to
  `com.gridscalr.desktop`, repeats those checks on the `.app.zip`, and the
  `checksums` job proves the merged `SHA256SUMS.txt` against every downloaded
  artifact.
- **No physical macOS or Windows install was verified for this release.** There
  is no Mac hardware and no Windows test machine in the project. Gatekeeper
  acceptance, dragging the app to Applications, a Finder double-click, the
  `.gridscalr` association on macOS, and the Windows installer, SmartScreen and
  uninstall path are **unverified on hardware**. CI proves the artifact, not the
  install.
- **The Linux artifacts were installed and launched on the Ubuntu build host.**
  The published `.deb` installed with `apt`, started under Xvfb and left the
  desktop entry and icon in place, then removed cleanly with `apt remove` (the
  `/usr/bin/gridscalr` binary was gone afterwards). The tarball extracted and its
  binary started the same way. The AppImage extracted (`--appimage-extract`) and
  its `AppRun` started; direct mounting needs FUSE, which the container does not
  provide. This proves packaging, install and launch, not the in-app workflows.
  An upgrade from 0.13.3 or 0.16.1 was not exercised, and the interactive
  checklist in `docs/releasing.md` step 7 remains the manual follow-up.
- **The builds remain unsigned.** There is no signing identity or notarization,
  so Windows SmartScreen and the macOS **Privacy & Security → Open Anyway** path
  stay part of the install instructions. Verify downloads with `SHA256SUMS.txt`.
- The release workflow never launches a packaged binary: the smoke commands are
  debug-only (F-037, F-074). The launch proof stays the packaged debug smoke test
  in CI on every pull request.

## Dependency position

- `glib 0.18.5` (`RUSTSEC-2024-0429`, medium, unsound) is **accepted with an
  expiry, not fixed**, because no upgrade clears it inside the current Tauri
  generation. It is Linux-only and not on the Windows or macOS code path. The
  reviewed acceptance runs to **2027-02-15** in
  `security/dependency-allowlist.json`; the dependency gate fails after that
  date and Dependabot alert
  [#1](https://github.com/MajorJohnDoe/gridscalr/security/dependabot/1) stays
  open so the state is not hidden.
- The evidence is recorded: `tauri 2.12.5` declares `gtk = "0.18"`, `gtk 0.18.2`
  requires `glib ^0.18`, `cargo update -p glib` resolves nothing, `glib` has no
  0.18 patch newer than 0.18.5, and the Tauri 3 pre-release still uses GTK3
  unless its optional `gtk4` path is taken. The clearing path is the Tauri 3 /
  GTK4 migration in
  [#270](https://github.com/MajorJohnDoe/gridscalr/issues/270).
- The dependency gate passes with **no npm finding** and **no unaccepted
  moderate-or-higher finding**. Five Rust warnings are accepted with a written
  reason and the same 2027-02-15 review date: `glib`, `proc-macro-error`,
  `zbus_names`, `zvariant` and `zvariant_derive`; `glib` is the one that needs
  the framework migration.

## No new drawing capability

This release adds no tool, measurement kind, symbol or export option beyond the
optional-content serialization fix. 0.28.0 is a correctness, storage and
verification release, and 1.0.0 is intended to be the same product with a frozen
format and proven artifacts.

## Schema and upgrade notes

- **Schema 27 requires migration.** 0.28.0 writes schema 27. Projects from any
  earlier release open through the existing ladder and are migrated when opened;
  the 26 → 27 step adds no field and changes no byte, so a schema 26 project
  renders exactly as before.
- **Schema 27 is frozen for 1.0.** A later format change is a schema 28 and a
  deliberate unfreeze, not a routine migration. The compatibility promise and the
  committed schema 1–27 corpus extend to 27 and stop there.
- No source file is written, moved or re-encoded by the upgrade. A TIF document
  keeps its embedded PDF until a save or import path can build its cache from a
  reachable scan; a project that cannot write the cache keeps its embedded bytes
  and is never made lossy.
- The browser fallback cannot write a cache beside the project, so a colour scan
  downloaded there keeps its derived PDF inside the project JSON. Use the
  desktop app for cache-backed colour scans.

## Known and accepted issues

- Acrobat and PDF-XChange verification of the nested optional-content form is
  pending in [#257](https://github.com/MajorJohnDoe/gridscalr/issues/257).
- No physical macOS or Windows install is verified, the Linux install matrix is
  open, and every artifact is unsigned.
- The macOS release artifact has no launch proof in the release profile
  (F-117); the packaged smoke test runs against debug builds in CI.
- `glib 0.18.5` remains accepted until the Tauri 3 / GTK4 migration
  ([#270](https://github.com/MajorJohnDoe/gridscalr/issues/270)).
- **Save a copy** does not rewrite `derivedPdf.relativePath` (F-115); use
  **Share project package…** for a self-contained copy.
- A stale cache for a replaced scan stays on disk as an unreferenced file. The
  project doctor reports a stale or invalid marker but never deletes a cache
  automatically.
- The Pages list still renders at most 400 cards, and recovery autosave keeps its
  documented 64 MiB per project / 256 MiB total budget.
