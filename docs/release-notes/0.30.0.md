# GridScalr 0.30.0

0.30.0 is a takeoff-interface release. It gives the counting and quantity
surfaces one vocabulary, one settings home and a standard takeoff table that can
always be placed. No measurement, schedule, CSV or export capability is added,
and **the project-file schema does not change**: schema 28 stays the current
development schema and every project opens exactly as before.

This release was published on 2026-11-20.

## One vocabulary

- The right-dock tab, the **View** menu entry and the inspector tab are
  **Takeoff** (Swedish **Mängdning**).
- A saved table is a **takeoff table** (Swedish **mängdschema**) in the picker,
  the builder, the placement dialog, the inspector, the CSV dialogs and the
  diagnostics.
- The procurement dialog is **Order…** (Swedish **Beställning…**), and a card's
  source list is **Fed by** (Swedish **Matas av**).
- The built-in category view is labelled **Preview – cannot be placed** and
  states why it cannot be placed, edited or exported.
- Every disabled takeoff control names the reason in visible text, and each one
  points at that text with `aria-describedby`.

## Takeoff settings hub

All takeoff setup lives in one modal, **View → Takeoff settings…**. The gear in
the Takeoff tab and a single link row in **Project settings → Display** open the
same hub; Project settings no longer has its own Quantities, Count types or
Fields sections.

| Tab | What it owns |
| --- | --- |
| **Objects** | Measured objects (categories) and counted objects (count types) in one list with a **Type** column, the project default category, waste and rounding, and one **Add object** action that chooses the kind. |
| **Fields** | The measurement and space fields, their applies-to rules, the field sets and **Manage fields…**, which opens the same editor the inspector uses. |
| **Tables** | The saved takeoff tables with edit, duplicate, delete and **New takeoff table…**. |
| **Cards** | The four KPI cards with a **Show card** switch and the **Fed by** lists for Walls and Doors. Rooms and Area explain that they read the space register. |

Deep links open the hub on the right tab and row: an empty card's **Configure**
opens Cards on that card (Rooms and Area open the space register instead), and
**Edit object “…”** in Properties opens Objects on that object. The hub refuses
a view-only session instead of showing controls whose edits the store would
ignore.

Roles without a card (floor, ceiling, roof and other) are preserved in the
project and are not exposed until a card uses them. A card reads the explicit
**Fed by** ticks, never a name, so a missing source shows 0 with a **Configure**
action rather than a wrong number.

## Standard takeoff table

Opening the Takeoff tab still writes nothing: no table, no revision bump and no
dirty flag. A project with no takeoff table shows **Preview – cannot be placed**
with two actions:

- **Create takeoff table** adds the **Standard** table with the columns
  **Object**, **Count**, **Unit** and **Value**, one row per item and no
  filters, and selects it so Place, Edit and Export CSV work immediately.
- **Create takeoff table and place…** asks the placement questions first, then
  writes the table and the placement in one undo step and reports **Standard
  takeoff table created**. Cancel writes nothing.

The standard table is an ordinary takeoff table, not a new kind of data: rename
it or change its columns, filters, grouping and totals in the builder. Placement
keeps the existing draw-layer rule — the active draw layer, an existing draw
layer, or a new draw layer named **Takeoff tables** — and never uses a
measurement layer. A project with saved tables opens on the first one without
writing anything; choosing the built-in preview from the picker remains a
deliberate, non-placeable view.

## Interaction, dialog windows and the placed table

The same release fixes how the lists and dialogs behave, and gives a placed
table the calm banded look of the reference style.

- **Row reordering works with the mouse on Windows 11 again.** Pages, layers and
  the takeoff builder columns are dragged with a pointer gesture instead of the
  HTML5 drag events that the desktop shell's own file-drop target swallowed.
  Drop line, multi-select drag, auto-scroll, `Alt+Arrow` and one undo per drop
  are unchanged, and dropping a PDF, TIF or `.gridscalr` on the window or on the
  Pages panel still opens it.
- **One home for measurement settings.** The **New measurement** settings —
  category, room, preset, count type, pieces, area shape/mode — and the target
  layer now live in the measurement tool flyout. The compact context-bar summary
  opens the same panel; there is no second editor. Family flyouts open on a
  normal left-click, and long-press or right-click still opens them for touch and
  pen.
- **Dialogs behave like desktop windows.** Every work dialog with a close control
  can be dragged by its header and no longer dims or blocks the drawing, so a
  value can be read from the plan while a dialog is open. Focus still enters the
  dialog, `Tab` can leave and return, `Escape` closes the focused or topmost
  window, and focus returns to whatever opened it. Destructive confirmations
  revalidate their object by id, so a change behind the dialog cannot apply the
  action to the wrong item. The help image viewer is the one deliberate
  full-screen exception.
- **The takeoff table builder keeps its actions in reach.** **Save**,
  **Duplicate** and **Delete** sit in the dialog header beside the close control
  instead of the bottom of a long scrolling form.
- **The placed takeoff table is restyled.** A light grey header band, subtle
  alternating rows, a group header and subtotal per group and a distinct grand
  total, all from theme tokens so every palette stays readable. The canvas and
  the exported PDF draw the same layout, so only the font measurement differs.

## Deliberate gaps

- Only the four cards exist. Unused roles are kept but not exposed, and a custom
  card or a card-owned multi-source KPI is not part of this release.
- One takeoff table reads one source, measurements or spaces. There is no
  joined or cross-source table.
- No takeoff table is created when the project or the tab opens. The standard
  table exists only after the explicit create action.
- Dialog windows are not repositioned to a remembered place: a reopened dialog
  returns to the centre, and window positions are not part of the project file.
- The right-dock takeoff table and the quantity report keep their own styling;
  only the table placed on the drawing and in the drawing PDF uses the new banded
  palette.

## No schema change

`SCHEMA_VERSION` stays **28**, the version shipped in 0.29.0. No project field,
migration step, fixture or compatibility promise changes, and a 0.30.0 project
is a schema 28 project. `settings.summary`, `summaryRole`, schedules and
placements keep their stored shape.

## Upgrade notes

- There is nothing to migrate. Open a schema 28 project as before; no file is
  converted and no data is rewritten.
- Project settings no longer contains Quantities, Count types or Fields. Use
  **View → Takeoff settings…** for all of them; the settings themselves are
  unchanged and undoable exactly as before.
- Shortcut labels are unchanged: **Takeoff** is still `Ctrl/Cmd+Alt+S` and
  **Order** is still `Ctrl/Cmd+Alt+Q`.
