# GridScalr 0.20.0

This release makes large drawing sets a tested, supported use case, gives the
reference pane its own page navigation, and makes save, project-size and
source-file status visible in the shell.

## Large projects

- **Reference project benchmark.** `npm run bench:large` builds a deterministic
  150-page, 15,000-item project with 60 embedded images and reports mutation,
  serialization, open, page-switch and autosave timings. The budgets are
  documented in `docs/limitations.md`.
- **Virtualised Markups table.** Only the rows around the viewport are created.
  The reference benchmark renders 15 rows for 15,060 items and opens the panel in
  about 140 ms on the development machine.
- **Adaptive undo history.** History keeps up to 80 snapshots for small projects
  and shrinks towards four when a serialized snapshot exceeds the 48-million-
  character budget, instead of exhausting memory.
- **Canvas viewport culling.** Items, labels and symbol tags outside the visible
  viewport are skipped without changing the rendered result.
- **Faster autosave.** Recovery stores one serialized snapshot, skips an
  unchanged project revision, and keeps older object-shaped records readable.

## Reference pane

- **Independent page navigation.** The reference bar now has previous/next page
  buttons, a page number and **Follow primary**. A detail sheet can stay in the
  reference pane while measuring on another sheet. Zoom and pan stay linked, and
  switching source returns the pane to the primary page.
- **Correct comparison navigation.** Added or removed comparison items open their
  page in the reference pane instead of moving the editable project.

## Shell and status

- **Saved state in the status bar.** The shell shows **Saved**, **Unsaved
  changes** or **Not saved to a file**.
- **Source-drawing warnings.** Missing drawings and drawings whose file size
  changed on disk are marked in the status bar before an export fails.
- **Project size and sources.** Project settings reports the project data size,
  embedded image and OCR contribution, item/page counts and per-document source
  status.
- **Recovery and recent-file controls.** Preferences → Data clears the recovery
  snapshot or recent-file list, and single missing entries can be removed. The
  welcome screen marks missing recent files and has an empty state.
- **Laptop layouts.** New responsive rules keep menus, tools, status controls and
  primary actions in view at common laptop widths and 150–200 % OS scaling.

## Code health and tests

- Integration modules, canvas pointer handling, item rendering and styles were
  split into feature and canvas modules with blocking file budgets.
- Coverage thresholds, deterministic fuzzing and a four-screen visual regression
  gate run in CI.

## Compatibility

The project-file schema remains **23**. No migration is needed. Existing
projects, packages, reference sessions and exports keep their current content.

Source status compares existence and byte size while a project is open; a change
that preserves the byte size is detected by the normal checksum check when the
project is reopened. See `docs/limitations.md`.
