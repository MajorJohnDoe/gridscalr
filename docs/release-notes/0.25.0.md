# GridScalr 0.25.0

This release makes the workspace behave like one tool. Pages can be dragged,
dropped, inserted and reordered with the keyboard; a drawing can be dropped
straight onto the Pages panel; the Pages, Layers and Markups lists share one
focus, selection and move model; and layers can be nested into groups with
inherited visibility and locking. The project doctor grows source-availability
checks, managed-copy cleanup and a repair preview, imported pages show where they
came from, TIF import reads far more scans, and a TIF source can now be replaced
like a PDF.

The project format moves to **schema 26**. The migration is deterministic and
additive: an existing project opens with no layer reparented and no ID generated.

## Download

Windows portable, NSIS and MSI builds, one universal macOS DMG and app zip, and
Linux AppImage, deb and tarball are published on the GitHub Release for
`v0.25.0`, together with `SHA256SUMS.txt`. The builds are unsigned; see
**Install** below.

## Pages

- **Drag and drop.** Drag a page card, or the grip in its corner, to change the
  project page order. A drop line shows the insertion point, the panel scrolls
  near its edges, and a drop that changes nothing writes no checkpoint.
  `Ctrl`/`Cmd` + click and `Shift` + click build a selection, and dragging any
  selected card moves the whole block.
- **Keyboard reorder.** `Alt` + `Up` / `Down` moves the selection one position,
  `Alt` + `Home` / `End` moves it to the ends, and `ArrowUp` / `ArrowDown` /
  `Home` / `End` move focus without changing the selection. Every move is
  announced to screen readers and returns focus to the moved page.
- **Undo.** A reorder, an insert and a pages-panel drawing drop are each exactly
  one undo step. Undo restores the previous `PageId` order and every page's
  state, and the canvas, thumbnails and page sizes follow. A drop that changes
  nothing adds no history entry. Duplicate, delete, document import and source
  replacement stay explicit, non-undoable and checkpointed.
- **Page menu.** The card menu now carries **Insert page before…**, **Insert page
  after…**, **Move page to position…**, **Duplicate page…** and **Delete page…**
  beside the navigation, rename, sheet and source actions. Insert names the
  target position in the item and repeats it in the confirmation, for example
  `before page 3 — Sheet A-101`. `Shift+F10` and the Menu key open the menu
  without a pointer.
- **Status badges and filters.** Compact badges flag a changed source file, a
  superseded source, missing or stale OCR, a locked scale, calibration, blank and
  template sheets and the item count. A filter bar narrows the list to **All**,
  **Changed source**, **Superseded**, **OCR missing or stale** or **Scale
  locked**, with a count per filter and a pressed state on the active one. The
  filter is session state and is never written to the project. Drag and file
  drops are disabled while a filter hides pages, because the drop position would
  be ambiguous; the page menu and shortcuts keep working by page ID.
- **Drop a drawing on Pages.** A PDF or TIF dropped on the page cards opens the
  existing page picker and import preflight, and its pages land at the drop line.
  The whole import is one undo step. A dropped `.gridscalr` project never opens
  over the current project, and a multi-file or unsupported drop is refused with
  a message.

## One interaction model for Pages, Layers and Markups

The three lists now share one model for row focus, `Ctrl`/`Cmd` and `Shift`
selection, block moves, pointer insertion, filters and collapse state.

- `Shift+F10` or the Menu key opens the row menu and restores focus; `F2`
  renames where inline rename exists; `Enter`/`Space` activates the focused row.
- Pages and Layers keep their own order semantics: a page moves through the
  undoable page action, a layer moves inside its kind group. Markups is a sorted,
  grouped virtualised table, so it follows the focus, selection, filter and
  collapse conventions but has no drag handle or drop line.
- The Layers panel gains a search field, expand-all and collapse-all, a shared
  drag handle and drop line, filtered reorder that keeps unlisted layers in their
  slots, and `Shift`-range item selection.
- Markups favourites are shown first in the view picker and stay a per-machine
  convenience; saved views still travel in the project.

## Import provenance

An imported page keeps the source project's stable ID, the source revision
SHA-256, size and modification time, the source page ID, the import time and the
importing GridScalr version. Properties shows a read-only **Imported page**
section for that page, and the Markups table adds a compact **Imported** column
only when a visible row actually has provenance. The column is derived per
render and is not written into saved views. A normal page renders no section and
no empty heading.

The revision hash is now computed over the raw `.gridscalr` bytes, so it matches
the checksum shown for packages and backups. Pages imported by an older release
keep their historical decoded-text hash and are not rewritten.

## Project doctor

- **Repair preview.** One planner produces both the preview and the repaired
  copy, so a preview cannot drift from the result. It records every concrete
  decision — duplicate `from → to` renames, removed pages, items and count
  presets, rewritten or cleared references, obsolete page ranges and removed
  stale OCR — with the validator code each change addresses and before/after
  error and warning counts.
- **Filters.** The issue list filters by severity, entity kind (including OCR)
  and repair availability. A filter only narrows the shown list; it never changes
  which repairs exist. **Select all shown repairs** adds only the repairs for the
  filtered issues and never deselects.
- **Sources.** Every external drawing is reported as available, missing or
  changed, and reference drawings are separated from managed copies. A missing or
  changed source is a warning with **Relink…** and **Copy into project**, never a
  save gate. Source actions are only offered for an open, writable project and are
  disabled after an in-memory repair until the repaired copy is saved.
- **Unused managed copies.** The same section lists files in `<project>.drawings/`
  that no document references, with a size total, per-file selection and an
  explicit confirmation. The folder and the reference set are checked again
  immediately before each deletion, so a copy that is still referenced, became
  referenced, or vanished is skipped. Nothing is deleted automatically.
- Diagnostics stay path-free and add source counts only.

## Layer hierarchy and nested export (schema 26)

- A layer may carry an optional `parentId`. A group is an ordinary layer that
  other layers point at: there is no second order field and no folder entity, and
  paint order stays the order of the `layers` array, so grouping never restacks a
  drawing.
- **Inheritance.** Effective visibility is the layer's own visibility **and**
  every ancestor's; effective locking is its own locking **or** any ancestor's. A
  hidden group cannot render, hit-test or export, and a locked group cannot be
  edited. The row shows **Hidden by “Group”** or **Locked by “Group”** with the
  ancestor named in the tooltip.
- **The Layers panel is a tree.** Rows show an indent, a collapse chevron, a
  folder icon and a nested-layer count. Drag on the middle of a row to nest, the
  top and bottom bands to reorder, and a rejected drop shows the reason on the
  drop line and in the live region. `Alt` + `Right` nests, `Alt` + `Left` moves a
  layer out of its group, `Alt` + arrows moves among siblings, and plain
  `Left`/`Right` collapses or expands the focused row. Every move is one undo
  step.
- **Subtree rules.** Duplicating a group copies its whole subtree with fresh layer
  and item IDs. Deleting a group requires a confirmation that names the nested
  layer and item counts, and a page deletion keeps a group while any descendant
  is still referenced.
- **Invalid references are reported, never silently repaired.** A missing parent,
  a cycle, a cross-kind link and an invalid parent value are validator issues for
  the project doctor.
- **Optional-content export** writes the visible hierarchy as nested heading
  dictionaries in `/OCProperties /D /Order`, excludes a hidden ancestor's whole
  subtree, never writes a group with no visible content, and keeps the flattened
  default byte-identical.
- **Migration.** Schema 25 → 26 adds nothing to an existing file: every layer
  becomes a root, every layer, item, page and document ID is preserved, and no ID
  is generated.

## TIF sources and scans

- **Replace source… for TIF.** A TIF document can now be replaced by another
  TIF, using the same page mapping, superseded-page handling and single
  checkpoint as a PDF. The picked scan is converted to its derived PDF and the
  document keeps the raw TIF SHA-256, so a revision is compared against the bytes
  that were actually picked. The page menu offers **Replace source…** for a TIF
  source, while reload, relink, use-current and managed-copy actions stay
  PDF-only; a file of the wrong kind is refused with a message. Calibration,
  page-count, page-size and locked-scale warnings are shown for both formats.
- **More codecs.** Stripped scans with no compression, PackBits, LZW and
  Deflate/Flate now import, including horizontal predictor 2. Greyscale and RGB(A)
  at 1, 2, 4, 8 and 16 bits decode; 1-bit greyscale stays a 1-bit PDF image,
  2/4-bit greyscale expands to 8 bits, 16-bit samples use the high byte and RGBA
  is composited over white. Decoding is per strip to bound peak memory, and the
  same bytes always produce the same PDF bytes.
- **JPEG and tiles.** JPEG-in-TIFF (compression 7, and old-style 6 with a complete
  interchange stream) is embedded through `/DCTDecode` without re-encoding, with
  a shared `JPEGTables` set joined to each abbreviated strip. Greyscale, YCbCr,
  RGB and CMYK streams are accepted. Tiled layouts (tags 322–325) are validated
  and composed into one band per tile row with cropped edge tiles, so a tiled page
  imports at the same size and pixels as a stripped page.
- The limits stay explicit: palette colour, JPEG 2000, tiled JPEG, tiled CCITT,
  per-strip old-style JPEG without a complete stream, YCCK, planar channels,
  signed or floating-point samples, tile grids over 65 536 tiles and pages over
  256 MB of decoded colour data are rejected with a localized reason. None writes
  a blank or black page.

## Import preflight relink

The import preflight is now a per-document source review. Each selected document
shows whether it is verified, missing, checksum changed or page-count changed,
plus how many selected pages are importable. A missing PDF offers **Relink…**,
which verifies readability, page count and raw-byte SHA-256 before the in-memory
import is rebuilt. A changed checksum or page count never imports silently:
**Import pages** stays disabled until **Use anyway** is chosen for that file, or a
correct copy is relinked. **Forget relink** returns the document to the path
recorded in the source project. Cancel, Escape and the close button leave the
project and every source file untouched.

## Internal gates

- **Rust source budget.** `npm run check:file-budgets` scans `src-tauri/src` in
  the same command as the frontend, with a 400-line hard limit and a 300-line
  target. `src-tauri/src/{commands,package,project_write,source_copy}.rs` are
  reviewed exceptions with a stated reason. `--update` raises an existing
  exception, prunes one whose file disappeared, and refuses a new oversized Rust
  file.
- **Model boundary.** Built-in count types and the schematic symbol catalogue
  moved into `src/model`, so `model` has no `features/` import left. An ESLint
  rule and `tests/modelBoundary.test.ts` enforce the direction without an
  allowlist.
- **Renderer page order.** One store subscription derives the renderer display
  order from the project page list and the undo restore, so the scattered
  `setPageOrder()` calls are gone and the page order is never a second source of
  truth.

## Known and accepted issues

- The Pages panel renders at most 400 cards. A status filter narrows the list
  before that cap, but a matching page beyond it cannot be selected or reordered
  (F-075).
- Page duplicate and delete stay per page even with a multi-page selection,
  because both are structural (F-080). A managed copy accepted after a dropped
  drawing is a second history boundary, so Undo does not remove that import
  (F-076).
- **OCR missing** is limited to TIF pages; a scanned PDF page has no cheap way to
  prove its text layer is empty before extraction (F-078).
- Import provenance stores the source project's stable ID, not its display name,
  so the UI shows a shortened ID (F-083).
- Unused-copy cleanup inventories the top level of the drawings folder only, and
  only `.pdf` files (F-084). A repairable issue code whose plan is empty leaves
  **Apply selected repairs** disabled (F-085).
- pdf.js, and therefore Firefox's built-in viewer, reads only the array form of a
  named optional-content group, so it lists the exported hierarchy flat instead
  of nested. The groups themselves are present and toggleable (F-087).
- Replacing a managed-copy source leaves the old managed file on disk and can
  keep stale `originalPath`/`originalSha256` while the new document becomes a
  reference (F-088).
- RGBA TIFF transparency is flattened over white (F-089), 16-bit samples are
  reduced to 8 bits (F-090), a decoded colour page is stored as an embedded PDF so
  it grows the project (F-091), and predictor 2 is refused below 8 bits (F-092).
  Tiled JPEG needs a decoder (F-093), old-style JPEG only works through a complete
  interchange stream (F-094), and CMYK passthrough follows the stored sample
  convention and the Adobe marker (F-095).
- The import picker still hides pages of a missing document before the preflight
  can offer a relink, so the picker's own **Locate…** remains the primary path for
  a moved project (F-096).
- The Rust gate checks file size, not module boundaries (F-097). The schematics
  feature still has no `index.ts` surface and is outside the foundation boundary
  check (F-098). Document registration still happens after the store emit, which
  is a legitimate deferred state rather than an error (F-099).
- The Linux GTK stack still resolves `glib 0.18.5`, accepted by the dependency
  gate with a written reason and tracked in
  [#21](https://github.com/MajorJohnDoe/gridscalr/issues/21). The audit follow-ups
  [#199](https://github.com/MajorJohnDoe/gridscalr/issues/199),
  [#200](https://github.com/MajorJohnDoe/gridscalr/issues/200) and
  [#201](https://github.com/MajorJohnDoe/gridscalr/issues/201) remain open.

## Upgrade notes

- A schema 25 project opens directly. The migration adds no `parentId`, moves no
  file and generates no ID; the Layers panel shows the same flat list until you
  nest a layer yourself.
- A reorder, an insert and a pages-panel drawing drop are undoable and still
  write their recovery checkpoint. Duplicate, delete, document import and source
  replacement keep clearing undo history and cannot be undone.
- A filter on the Pages panel is session state. It is not stored in the project
  and does not travel with a package.
- Existing provenance recorded before 0.25.0 keeps its decoded-text revision hash
  and is shown as historical. New imports record the raw-byte hash.
- A TIF source is replaced by a TIF and a PDF source by a PDF, because the
  document kind, embedded derived PDF and raw checksum must stay consistent.
- Favourites in the Markups view picker stay local to the machine and are not
  added to the project file.

## Compatibility and migration

The project-file schema is **26**, up from 25. A 0.24.0 or older build refuses a
schema 26 file with a newer-version message rather than opening it with the layer
hierarchy dropped, so a project saved by 0.25.0 must be opened with a 0.25.0
build. Every older schema still migrates forward on open, and the committed
`fixtures/legacy/` corpus covers schema 1–26.

Source PDFs and TIFs are still never modified. Reference and managed-copy modes,
**Consolidate drawings…**, **Share project package…** and the conditional save
behave as in 0.24.0. A project saved by 0.25.0 uses schema 26; open it with a
0.25.0 build.
