# GridScalr 0.24.0

This release makes the 0.23 file-safety model visible and controllable, and
hardens the desktop surface that reads project files, drawings and packages. It
adds an autosave preference, a recovery center, a backup manager, a true
view-only mode, a project status popover and conflicted-copy management, all on
top of an independent security audit of the Tauri capabilities, the Content
Security Policy, the filesystem guards and the dependency surface.

The project format stays **schema 25**. Existing projects open without a
migration, and no project field changes in this release.

## Recovery and backups

- **Autosave preference.** **Preferences → Data** turns autosave on or off,
  chooses a 15, 30 or 60 second interval and offers **Pause for this session**.
  Autosave is still on at 15 seconds by default. It writes recovery snapshots
  and never the project file; turning it off or pausing stops only the periodic
  snapshots. Structural checkpoints are still written before page, source and
  import operations.
- **Recovery center.** The welcome screen and **Preferences → Data → Open
  recovery center…** open one dialog listing every autosave and checkpoint,
  grouped by project and app instance. Each record shows its save time, size,
  project name and path, app instance and whether its base file still matches
  the file on disk. **Restore selected** and **Delete selected** act on exactly
  one record; an older, unknown or missing base asks for a second confirmation.
  Nothing is restored automatically.
- **Byte budget and pruning.** Recovery storage is bounded at **64 MiB per
  project and 256 MiB for the whole store**, in addition to the existing record
  counts. The newest autosave and newest checkpoint of every project are never
  pruned; older records are removed oldest first before a write. The recovery
  center and diagnostics show the total and per-project size, and a full store
  shows a **Recovery storage full** chip that opens the center.
- **Backup manager.** **File → Backup manager…** lists every rolling backup of
  the open project with its time, size and the path it was written from.
  **Restore as copy** is the default and opens the backup as unsaved work.
  **Replace open project** is offered for a saved project and binds the backup
  to the current path after a separate confirmation; nothing is written until
  you save. **Delete selected** and **Delete all** ask for confirmation and
  never touch the project file or a drawing. The number kept per project is a
  2–10 preference in **Preferences → Data** (default 3) and applies on the next
  successful save.
- **Restore with located drawings.** A restored backup resolves relative
  drawing links from the project path recorded with that backup and, when that
  folder no longer exists, from the folder of the open project. Drawings that
  cannot be found are listed before the restore starts with **Locate
  drawings…**, and each located file keeps its checksum check. A stale absolute
  path is reported, never loaded in place of the recorded relative link.
- **Conflicted copies from File and Recovery.** **File → Conflicted copies…**
  and **Manage conflicted copies…** in the status popover list the copies beside
  the open project with their name, time and size. **Open as project** loads one
  as its own project without writing the original, **Compare with open project**
  opens the read-only revision comparison, and **Delete selected** removes one
  file after confirmation. Discovery matches only the documented name in the
  project's own folder, never follows a symbolic link and never deletes
  automatically. The last remaining copy is protected when the original project
  file is missing.

## View-only and project status

- **True view-only.** A session opened view-only now disables every project
  mutation: tools, inline editors, drag, resize, rotate, vertex edits, bulk
  edits, layer and category changes, page changes, property fields, delete,
  paste, OCR storage and the matching menu entries and shortcuts. Pan, zoom,
  page navigation, search, the reference pane, export, package and **Save a
  copy…** keep working. A normal Save and Save As are refused.
- **Take over to edit.** The banner and the status bar say **View-only**.
  **Take over to edit** re-checks the sidecar lock before enabling editing and
  refuses while another live window still owns the project. Taking over is
  explicit; nothing enables editing silently.
- **Project status popover.** The saved/unsaved chip is now a button that opens
  a compact summary: the last save time, the last automatic backup, the autosave
  state and interval, pending validation warnings and blocking errors, whether a
  recovery record is available, and how many conflicted copies sit beside the
  project. It offers **Backup now**, **Review recovery…**, **Open project
  doctor…**, **Manage conflicted copies…** and, while autosave is on, **Pause
  autosave for this session** or **Resume autosave**. It is rebuilt from live
  state each time it opens and never polls the disk or writes anything by
  itself.
- **Autosave status.** The status bar continues to show **Autosave · 15 s**,
  **Autosave off** or **Autosave paused**, and keeps a persistent **Autosave
  failing** or **Recovery storage full** chip until a later write succeeds.

## Security hardening

- **One production Content Security Policy.** The Tauri response header is now
  the only shipped page policy. It has no development origin, adds `object-src`,
  `base-uri`, `frame-src` and `form-action`, and no longer needs
  `style-src 'unsafe-inline'`. A dev-server meta policy exists only in the
  browser fallback. The boot styles moved to `public/boot.css`, and a CSP
  violation is reported on the boot panel instead of a blank window.
- **Workers inherit the policy.** PDF.js and Tesseract start from blob shims so
  both inherit the document policy; a blob worker cannot fetch a remote origin.
  The packaged smoke test loads a PDF page and runs the OCR worker in a real
  production-CSP build on every platform.
- **Smaller capability set.** `core:default` is replaced by `core:event:default`,
  six explicit window permissions and the two dialog permissions the app uses.
  The debug-only smoke commands are compiled out of release builds.
- **Path and package hardening.** A shared Rust guard resolves absolute paths
  and symlinks and junctions, normalises `\\?\` and UNC spellings, compares
  case-insensitively and enforces managed-folder containment. Project reads are
  capped at 256 MB, source reads at 1 GiB and backup writes at 256 MB. Package
  extraction is limited to 2 GiB uncompressed, 1 GiB per entry and 2 GiB for the
  ZIP, shows the unpacked size before extracting and checks free space with a
  64 MiB reserve. Archive entries with control characters, drive, UNC or
  backslash spellings are rejected during inspection and before writing, and a
  crashed save's stale temporary siblings are cleaned up on the next save.
- **Out-of-folder references are named.** A dismissible banner and the project
  doctor list drawings referenced outside the project folder and offer **Copy
  into project** or **Relink**. The reference itself stays valid; treat a
  project file as input and open only projects from a source you trust.
- **Sanitized error copies.** A path-bearing error dialog still keeps the raw
  detail on screen, but **Copy sanitized details** copies the same message with
  absolute paths replaced and the structured error code kept.
- **Dependency and advisory gate.** `npm run check:dependencies` audits the npm
  and Rust lock files on every pull request and before a release build. A new
  advisory at or above moderate fails unless it is accepted in a reviewed
  allowlist with a stated reason and an expiry date; the gate fails closed when
  an audit report cannot be read. The development-only `minimatch` advisory is
  fixed.
- **Adversarial input corpus.** A deterministic, seeded corpus now exercises
  protected-source spellings, managed-copy folder destinations, drive-relative
  targets, package entry names, case-variant duplicates, sizes, generated
  archive paths, packaged-project links, truncated JSON and the frontend/Rust
  limit parity. It runs in the normal frontend suite and in `npm run
  test:robustness`. It found and fixed two real defects: a managed-copy command
  that was refused once a project already held a managed copy, and generated
  archive names that kept DEL and C1 control characters.

## Known and accepted issues

- The dependency surface is **not advisory-free**. `glib 0.18.5`
  (RUSTSEC-2024-0429, a Linux-only soundness issue fixed in `glib 0.20.0`) is
  pinned by Tauri's GTK 0.18 generation and is accepted by the dependency gate
  with a written reason. It stays tracked by
  [#21](https://github.com/MajorJohnDoe/gridscalr/issues/21); it is not silently
  closed. Four unmaintained crates (`proc-macro-error`, `zvariant`,
  `zbus_names`, `zvariant_derive`) arrive through the same GTK and Linux
  single-instance path, have no known vulnerability and are accepted with the
  same 2027-02-11 review date. The npm production audit is clean.
- Three audit findings are out of scope for 0.24.0 and stay open:
  [#199](https://github.com/MajorJohnDoe/gridscalr/issues/199) runs the Rust
  path tests on Windows, [#200](https://github.com/MajorJohnDoe/gridscalr/issues/200)
  pins GitHub Actions to commit SHAs, and
  [#201](https://github.com/MajorJohnDoe/gridscalr/issues/201) makes PDF export
  bytes deterministic.

## Upgrade notes

- Autosave keeps its existing stored preference; an installation that never
  changed it stays on at 15 seconds. **Pause for this session** resets when
  GridScalr starts again.
- Recovery records written before the byte budget existed are still readable;
  their size is measured once when the center lists them.
- Backups written before this release have no origin path. They are still
  listed, restore through the open project's folder, and are never discarded
  because the metadata is missing.
- The 2–10 retention preference applies from the next successful save. Deleting
  backups or conflicted copies removes only the selected app-data or sibling
  files; project files and drawings are never touched.
- **Read-only** is now called **View-only** in the interface. The behavior is
  stricter than before: previously some commands could still change the
  project, and now every project mutation is blocked until **Take over to
  edit** succeeds.
- The desktop app still opens a project that changed on disk as view-only when
  another live window holds the lock, and a normal save still refuses to
  overwrite a changed file without an explicit choice.

## Compatibility and migration

The project-file schema is **25**, unchanged from 0.23.0. Projects created by
0.23.0 or earlier open directly with no migration, and projects saved by 0.24.0
keep the same schema. The new preferences (autosave and backup retention) are
app-level and are not written into the project file. The backup origin path is
stored in an optional `manifest.json` in the app-data backup folder, not in the
project.

Source PDFs and TIFs are still never modified. A reference or managed copy
keeps its existing mode, and **Consolidate drawings…**, **Use managed copy**,
**Detach from source** and **Share project package…** behave as in 0.23.0.
