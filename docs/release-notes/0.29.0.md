# GridScalr 0.29.0

> **Draft.** This note describes the next pre-1.0 minor on schema 28. The app
> version, tag, release artifacts and landing site are unchanged until the
> product owner decides the release. Nothing here is published.

0.29.0 is the first Drift Slice. It gives a drifttekniker or technical property
manager a complete local loop: define typed property fields, keep a room
register whose areas are derived from the drawing, read a live summary, place a
schedule table on the plan, and round-trip the same data through CSV and Excel.
The project file schema becomes **28**.

1.0 remains deferred. Schema 27 is no longer frozen for 1.0; schema 28 is the
current development schema. The compatibility promise and the committed
migration corpus now end at 28. Every later format change needs its own
migration, fixture, round-trip and determinism tests.

## Schema 28

Schema 28 adds the following project arrays and settings. A schema 27 project is
migrated deterministically when it is opened.

- `fieldDefinitions` and `fieldSets`: typed custom properties with a stable key
  per scope, options with stable ids, defaults, validation and an optional
  applies-to rule.
- `spaces`: buildings, floors, rooms and zones with an optional parent, room
  number, floor, usage, status, page link and space-scoped custom values.
- `schedules`: live definitions with built-in and `custom:<fieldId>` columns,
  filters, grouping, sorting and totals. One source per schedule in this slice:
  measurements or spaces.
- Schedule placements on drawing items (`kind: "schedule"`): the schedule id,
  the box, the row range, header and totals switches.
- `settings.summary`: the four card visibility switches.
- Optional `spaceId` and typed `custom` values on a measurement, and an optional
  `summaryRole` on a category or count type.

The 27 → 28 step **adds only empty arrays and the four default summary cards**.
It does not turn existing room text into spaces, assign summary roles or give
items custom values. Every document, page, layer, item, category, count type and
Markups view keeps its identity. A pre-28 file ignores the new fields, and a
pre-28 `schedule` item is reported as `droppedSchedulePlacement` rather than
rendered as a broken table.

The project doctor validates the new references, including field ids and keys,
enum options, space parents and cycles, measurement links, schedule columns and
filters, placements, custom values and summary cards. Deterministic repairs
cover duplicate ids and dangling links. Unknown custom keys and mistyped values
are reported instead of silently coerced. Duplicate room numbers are a warning,
not a save error.

## Custom fields

- Project settings → **Fields** defines text, number, number with unit, yes/no,
  date, single-choice and multi-choice fields with an optional unit, options,
  required marker, default, description, validation limits and applies-to rule.
- Fields can be ordered and grouped into named **field sets**. Applying a set
  fills each member's default value once on the selected measurement; it does
  not bind the item to the set and never overwrites an existing value.
- Properties gains a **Fields** section with the typed control for each field,
  inline validation, a required hint, a clear action and an explicit error when
  a stored value no longer matches its definition.
- A field's `key` and scope are permanent. A type change is blocked while values
  exist, and an in-use enum option cannot be removed. Deleting a field removes
  its values and field-set memberships in one undo step after a confirmation
  that names the value count.
- Space-scoped fields are filled in the space form and saved with the space.

## Rooms and spaces

- **View → Spaces…** opens a building → floor → room/zone register with room
  number, name, floor, usage, status, an optional page link and the area badge.
- A **Measured** space sums its visible linked area measurements, additions
  minus deductions, converted to m². Hidden items and hidden layers are
  excluded; locked measurements are included. A linked measurement without a
  page scale makes the area missing instead of understating it.
- A **Manual** area is a fallback only while nothing is linked. A linked
  measurement wins and the row says the manual value is unused.
- **Create rooms from the room text** creates one measured root room per unique
  room name and never links a measurement automatically. The register links and
  unlinks the current drawing selection, reveals a linked measurement, moves a
  space among its siblings and deletes a space after naming the link count.
- Deleting a page keeps its spaces and only clears the page link. Deleting a
  space unlinks its measurements but never deletes them. A space with child
  spaces is kept until the children are moved or deleted.

## Summary and schedules

- **View → Summary** (`Ctrl+Alt+S`) opens a third right-dock tab with four KPI
  cards — **Rooms**, **Area**, **Walls** and **Doors** — and a live table.
- A card reads an explicit `summaryRole` on a category or count type, never a
  name. A missing role shows 0 with a **Configure** action, and **Summary
  roles…** sets the roles in one undo step per change.
- The table shows the built-in category summary or a stored schedule, with page,
  category and space chips on top of the schedule's own filters. It is
  virtualised and scrolls sideways when the right dock is narrower than the
  schedule.
- **New schedule…** builds a definition with columns, grouping, sorting,
  filters and totals, and previews the first 20 rows with real totals. Rows can
  be **One row per item** or **Grouped**; grouped is read-only for CSV.
- A schedule that references an unknown field, a deleted page, category, count
  type or space reports it instead of hiding the column or crashing. Deleting a
  page, category, count type or space cleans the matching filter list.

## Placed tables and PDF output

- **Place on drawing…** puts a live table on a chosen page with a width in
  millimetres, a row range or all rows, and header and totals switches. It
  prefers the active draw layer, then an existing visible unlocked draw layer,
  then a new localized **Schedules** / **Scheman** layer; it is never created on
  a measurement layer.
- A placed table is an ordinary drawing item: it moves, resizes, rotates, locks,
  hides, duplicates with its page, follows layer visibility and locking, and
  updates when the drawing or the definition changes. Nothing is copied onto the
  item.
- Long content is ellipsized, the font never shrinks below 4.5 pt, and rows that
  still do not fit are reported as an overflow with **Continue on a new table**.
  There is no automatic pagination or repeated header in this slice.
- The drawing PDF export draws the same header, rows, subtotals and totals as
  vector text and lines from the one shared layout function. Page ranges, crop,
  layer selection, hidden items, hidden layers and locked items keep their
  existing rules.

## CSV round-trip and Excel

- **Export CSV…** writes one UTF-8 file with a BOM, the app locale's delimiter
  and decimal mark, an `ID` column, a `Typ` column and one `Label [key]` column
  per visible schedule field. Numeric cells stay numeric and formula-leading
  text is escaped with a leading apostrophe.
- **Import CSV…** is available for a one-row-per-item schedule. It detects the
  delimiter and BOM, maps a header by its bracketed key first and its label
  second, and shows a dry run with changed rows, before/after values, unchanged
  rows, unknown fields, duplicate headers and IDs, wrong row types, invalid
  values, read-only columns and rows absent from the file.
- A row with any invalid value is rejected as a whole. **Apply** updates only
  existing measurements and spaces through their stable id, never creates a row
  or an entity, and is one undo step. A project change made while the preview is
  open refuses the apply.
- Reference and derived columns (page, layer, category, space, count type,
  status, value, unit, area and timestamps) are exported but read-only, because
  the CSV shows display labels rather than stable references. Custom values are
  editable. A custom choice accepts its exact option id or unambiguous label,
  and a multi-choice uses semicolon-separated labels.
- Limits: UTF-8 only, at most 10 MB and 20 000 data rows. XLSX is not a schedule
  import or export format in this release.

## Compatibility and upgrade

- A schema 27 project opens normally and is migrated to 28 on open. The
  migration is additive and does not invent data.
- A schema 28 project is **not** readable by an older release. Finish the work
  in 0.29.0, or keep a copy before opening it in an older build.
- Saving is still a conditional write against the file version that was opened.
  A changed disk file is never overwritten without an explicit choice.
- The project file remains the source of truth; the placed table is a live view,
  and the CSV import is a controlled mutation of existing rows.

## Known limits in 0.29.0

Every deliberate gap from the slice is recorded in
[`../limitations.md`](../limitations.md). The main ones:

- The field editor has no field template (F-119), and opening it closes Project
  settings until it is closed (F-120).
- The space register is a modal, so selecting and linking cannot interleave
  (F-121), and it has no bulk move or subtree delete (F-122).
- A deleted custom field leaves its schedule column or filter reported as
  **Unknown field** (F-123).
- Summary card visibility has no editor (F-124), and wide schedules scroll
  sideways in the right dock (F-125).
- A total whose field has no visible column is computed but not shown (F-126).
- The Summary toolbar is rebuilt with the shell; focus is restored to the
  affected control, but the panel is not patched in place (F-127).
- A placed table has no automatic pagination or repeated header (F-128), and
  its overflow warning uses the canvas text metric rather than the PDF font
  (F-129).
- Schedule CSV cannot change reference or derived columns (F-130), a renamed
  custom option label makes an older value invalid (F-131), and import never
  creates rows or entities (F-132).
- Project page import does not merge the field, space or schedule registers, so
  an imported item can keep a source-only reference that the validator reports
  and the doctor can clear. The preflight warning stays open for a product
  decision (F-118).

## Measured performance

On the development container with Chromium, Node 24 and the browser fallback:

- 15 000-item summary: about 17–20 ms cold, effectively free when cached
  (target 100 ms).
- 10 000-row schedule with grouping, sorting and a total: about 192–195 ms cold
  (target 250 ms).
- Placed table layout over a 10 000-row source: about 2 ms for its visible
  window; a 1 000-row table renders at most about 26 rows plus overscan.
- 10 000-item, five-column CSV: about 210 ms export and 190 ms import plan
  (target 1 500 ms).

`GRIDSCALR_PERF_STRICT=1` asserts the documented targets; CI uses a looser hard
ceiling so a slow runner records a regression instead of failing intermittently.
The general large-project budgets are unchanged.

## Not in this release

Assets, issues, inspections, signoff, audit trail, QR codes, DWG/DXF, BCF/IFC/
FI2, PDF/A, redaction, cryptographic signatures, mobile, formulas, calculated
fields, cross-schedule references, multiple sources per schedule, custom-field
inheritance, XLSX import, schedule pagination beyond a row range and a
continuation placement, and any landing-site or release change remain outside
this slice.
