# GridScalr 0.32.0

0.32.0 adds an **opt-in performance panel** under **Help → Diagnostics** so a slow
session can be measured instead of guessed at. It ships off by default, records
nothing unless you enable it, and never uploads anything. No measurement,
schedule, CSV or export capability changes, and **the project-file schema does
not change**: schema 28 stays the current development schema and every project
opens exactly as before.

This release was published on 2026-11-23.

## Why a performance panel

A project that felt laggy on an older laptop could not be attributed to anything.
The app had no performance instrumentation: `performance.now()` appeared only in
the pen and palm-rejection helpers, so a stall could not be told apart from a slow
project save, a PDF rasterisation, memory pressure, or a drawing on a network
share. The documented `under 2 GB` working-set budget was a manual check with no
in-app readout.

The panel answers the question "what is slow right now?" with three signals that
are otherwise mixed together: the **main thread**, the **PDF worker** and
**memory**.

## What the panel shows

**Help → Diagnostics → Performance panel** opens a movable, non-modal window that
stays open above the drawing. Drag it by its header; it is clamped inside the
window. It reports:

| Row | Meaning |
| --- | --- |
| **Frame now** | The last frame interval: green below 20 ms, amber from 20 ms, red from 50 ms. |
| **Worst (30 s)** | The slowest frame in the last 30 seconds and how long ago it happened. |
| **Blocked** | Main-thread time that could not answer input in the last two seconds, and the long tasks that caused it. |
| **Heap** | Working set against the documented 2 GB budget. Windows only. |
| **Project** | Page, item and embedded-data counts for the project the numbers came from. |

The sparkline shows 30 seconds of frame time with a mark under every page render,
undo, save and autosave, so a spike can be tied to what caused it. **Show
details** adds a table of named spans with count, p50, p95 and max:

`serialize`, `shell-render`, `canvas-redraw`, `pdf-raster`,
`pdf-operator-list`, `thumbnail`, `autosave-write`, `project-open`.

**Hold** freezes the last window so a spike can be read after the fact, and
**Copy summary** copies the same technical block.

## Where it is enabled

- **Preferences → Diagnostics** has one switch, **Enable the performance panel**.
  It is off until you turn it on and is stored on this computer, never in the
  project file.
- **Help → Diagnostics** groups **Copy diagnostics**, **Report a problem…** and
  **Performance panel**. The menu entry is checkable.
- Closing the panel stops the recording: there is no invisible recording state.
  While it is enabled it samples from app start, so a slow project open can still
  be reported afterwards.

## In the diagnostics report

**Copy diagnostics** now appends a `Performance` block with the same window,
blocking, heap, project shape and span percentiles as the panel. It carries
counts, durations and sizes only — never a project name, item label or drawing
path — so it is safe to attach to a public issue. That is the intended support
loop: a user on a slow machine copies one block instead of installing a profiler.

## Instrumentation

Nine call sites gained one named span through the public `perfSpan` /
`perfMark` surface, and every entry point is a single boolean check while the
feature is off, so the canvas redraw and project save stay free:

- project serialisation in the store, with the serialized size as the span detail;
- shell render, canvas redraw, main page rasterisation and the PDF operator list;
- page thumbnails, autosave writes and project open;
- event marks for undo, redo, raster, save and autosave.

Each span is also written as a User Timing measure, so the panel and a devtools
Performance recording show the same data.

## Limits

- The heap row exists only on WebView2 (Windows). WebKitGTK and WKWebView expose
  no working set for the app, so the macOS and Linux memory row stays the manual
  desktop check.
- The panel is a support aid, not a benchmark and not a CI gate. It has no
  shortcut, so `docs/shortcuts.md` is unchanged.
- Nothing is recorded while the feature is disabled, nothing survives a restart
  and nothing is written to the project file.
- A measured regression is not fixed by this release; it is now measurable.
  `docs/limitations.md` records the panel's platform limits.
