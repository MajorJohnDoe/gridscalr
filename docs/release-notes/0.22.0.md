# GridScalr 0.22.0

This release adds the Medium Gray theme as the new default, an expandable tool
rail and a category menu for Project settings. It also hardens colour handling
across projects and improves the schematic symbol library.

## Themes

- **Medium Gray is the default.** New installations start in Medium Gray. System
  mode uses Medium Gray on dark systems and Light on light systems.
- **Five palettes.** **Default (medium gray)**, **Light**, **Dark Gray**,
  **Dark Jade** and **Navy** are selectable in **Settings → Preferences →
  General**. The previous Grey palette is now **Dark Gray**, and the original
  dark jade palette is now **Dark Jade**.
- **Existing preferences migrate.** Stored `grey` becomes `dark-grey` and the old
  `default` value becomes `jade`, so an explicit earlier choice is kept.
- **Theme showcase.** The README and the English and Swedish landing pages show
  one screenshot per theme. The images are regenerated with
  `npm run docs:capture` during the release documentation pass.
- **Readable secondary text.** Medium Gray secondary text and danger text meet
  the contrast targets on panels and raised surfaces.

## Workspace

- **Expandable tool rail.** The chevron at the top of the tool rail switches
  between one and two tool columns. The wider state is stored with the panel
  layout, survives restarts and resets from **Preferences → Workspace**.
- **Project settings categories.** Project settings now uses the same two-column
  category menu as Preferences: **Project**, **Report**, **Measurements**,
  **Display**, **Quantities** and **Stamps**. Count types and categories reopen
  the dialog on the Quantities category when their nested dialog closes.

## Colours and symbols

- **Colour handling is hardened.** Colours are parsed through a canonical
  `#rrggbb` parser for `#rgb`, `#rgba`, `#rrggbb`, `#rrggbbaa`, `rgb()` and
  `rgba()` values. Invalid item colours fall back to the layer or item default,
  invalid fill and text colours are dropped, and colour inputs can no longer
  display or commit black when the stored value is invalid.
- **No black fallback.** Canvas and PDF export resolve colours through the same
  layer-aware helpers, so invalid or missing colours never render or export as
  black.
- **Schematic previews follow the theme.** Symbol-library and context-bar
  previews use the current theme instead of a fixed near-white ink.
- **Rotary heat recovery redrawn.** The rotary recovery symbol now uses a large
  rotating loop with a clear arrowhead while keeping its id, ports and tag
  prefix.

Existing projects whose colours are already stored as black are not recoloured
automatically; the next edit uses a valid colour.

## Compatibility

The project-file schema remains **23**. No migration is needed. Existing
projects, packages, reference sessions and exports open unchanged.
