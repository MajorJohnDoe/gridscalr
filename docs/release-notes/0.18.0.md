# GridScalr 0.18.0

This is the language and output release: a Swedish user can complete the whole
workflow and send a professional procurement report. English remains the source
language and the fallback for every catalog key.

## Highlights

- **Complete Swedish and English interface.** The menu bar, tool rail, panels,
  inspector, status bar, canvas labels, dialogs, reports and export headings
  follow the selected language. Changing the language in Preferences relabels
  the open interface immediately, without a restart.
- **Locale-aware output.** Numbers, dates, CSV delimiters and decimal marks follow
  the active language. Swedish CSV uses semicolons and decimal commas by default;
  English uses commas and points. **Interchange (RFC 4180)** remains available in
  Preferences for scripts and other tools. XLSX keeps numeric cells.
- **Project metadata and report branding (schema 22).** Facility, client, project
  number, revision, author, report date, report title and notes are stored in the
  `.gridscalr` file and rendered on the quantity PDF and in the Excel summary.
  A PNG or JPEG logo can be embedded in the project and survives packaging.
- **Swedish quick start and help fallback.** The Quick start tab ships in Swedish,
  and the full English guide remains available with an explicit fallback note.
- **Consistent count schedules.** Built-in count types follow the interface
  language in the Count types dialog, Properties, Markups filter, quantity report
  and drawing PDF legend. Custom types keep their project-stored names.
- **Localized desktop errors.** Save, read, demo and package failures now show a
  localized headline and keep the operating system's technical detail on a
  separate line.
- **Bilingual symbol search.** All 52 facility symbols can be found by their
  English or Swedish name regardless of the active UI language.
- **Release hardening.** Duplicate catalog keys, single-word literals, direct
  element text and interpolated template literals now fail `npm run check:i18n`;
  the hard-coded baseline stays empty.

## Compatibility

The project-file schema is **22**. Projects saved with schema 21 and older load
normally and are migrated when opened; there are no manual steps. A project saved
by 0.18 should be opened with 0.18 or later.

Source PDF and TIF files are still referenced by path and SHA-256 and are never
overwritten. The local-first guarantees, portable `.gridscalr.zip` packages and
three-platform release artifacts are unchanged.

## Platform notes

The builds are not code-signed or notarized.

- **Windows 10/11:** SmartScreen may warn on the installer. Choose **More info →
  Run anyway** after comparing the SHA-256 hash with `SHA256SUMS.txt`.
- **macOS:** drag GridScalr from the DMG to Applications, then approve the
  unsigned app through **System Settings → Privacy & Security → Open Anyway**.
  The DMG is universal.
- **Linux x86_64:** install the `.deb`, run the AppImage after `chmod +x`, or
  unpack the tarball. The `.deb` desktop entry passes a double-clicked project to
  GridScalr; the AppImage does not yet forward the file because of an upstream
  Tauri limitation.

## Known limitations

- The full user guide and workflows remain English-only in 1.0. The Swedish UI
  includes the Swedish quick start and an explicit English fallback (#57).
- The static boot fallback in `index.html` is English until the selected catalog
  loads. The operating system's own error detail may also be in the system
  language.
- Windows 11 snap-layout hover is not shown on the app-drawn title row.
- The portable Windows executable and the AppImage do not register the
  `.gridscalr` file association.
- File dialogs, menu clicks and drag-and-drop are covered by the manual install
  checklist, not by the automated smoke test.
- The Linux GTK stack still resolves the documented `glib 0.18.5` advisory until a
  future Tauri/GTK upgrade (#21).

## Verification

- Frontend unit tests, Rust unit tests, Playwright smoke tests, the count
  workflow, canvas regressions and packaged `--smoke-test` runs on Linux, macOS
  and Windows.
- `npm run check:i18n`, `npm run check:docs`, `npm run check:versions`,
  `npm run lint`, `npm run format:check` and `npm run build`.
- Manual clean-install checks remain in the release checklist for each platform.
