# GridScalr 0.23.0

This release completes the foundation work: safer saving, scoped recovery,
stable page identity, explicit source storage, integrity checks and optional
PDF interoperability. It is the largest project-file change since the
multi-document model, and it ships with a schema migration from every earlier
version.

## Saving and recovery

- **Conditional saves.** A normal save is a compare-and-swap against the file
  version GridScalr loaded. If the file changed on disk, the save is refused
  until you choose an action.
- **Conflicted copies.** The default conflict action is **Save as conflicted
  copy**, which keeps both versions. **Reload from disk**, **Overwrite** and
  **Cancel** are explicit alternatives.
- **Real disk comparison.** **Compare with disk version** shows the differences
  between the local project and the file on disk using the revision comparison
  engine. It is read-only.
- **Read-back verification.** A successful save is read back and hashed before
  the project is marked saved.
- **Rolling backups.** Up to three automatic backups are kept in app data, with
  **File → Back up now…** and **File → Restore backup…**. Restored backups open
  as unsaved copies.
- **No-op saves.** An unchanged project is not rewritten.
- **Scoped autosave.** Recovery records are keyed by project and instance and
  carry the base file hash. Opening a project shows a recovery chooser instead
  of silently restoring an older snapshot.
- **Advisory leases.** A project open in another instance warns on open and
  offers **Open read-only**, **Take over** or **Cancel**. A stale or corrupt
  lease never blocks. The lease is a warning; the conditional write is the
  safety mechanism.
- **Structural checkpoints.** Destructive page and document actions write a
  labelled recovery checkpoint before they run.

## Pages and documents

- **Stable page IDs (schema 24).** `Project.pages` is an ordered page list and
  every item, layer home page and page-state key uses a stable `PageId`. Display
  numbers are derived from the order.
- **Insert, reorder, duplicate and delete.** Pages can be dragged into a new
  order, inserted at a chosen position, duplicated and deleted without moving an
  item to another page.
- **Empty projects.** A blank project with zero pages and documents is valid and
  can be filled by importing pages later.
- **Replace source…** maps pages from a new revision to the existing pages,
  keeps mapped page IDs and items, and leaves unmatched pages on a superseded
  document until an explicit cleanup.
- **Import preflight.** Importing pages from another project shows pages, items,
  categories, count types, line types, assets, missing files and checksum
  warnings before anything changes. One import is still one undo step.
- **Import provenance.** Imported pages record the source project, revision,
  source page and import time without breaking older files.

## Source storage

- **Reference and managed-copy modes (schema 25).** A document explicitly
  declares whether it references its original file or uses a verified copy.
- **Copy drawing into project.** Managed copies live in
  `<project>.drawings/<name>-<hash8>.pdf` and are referenced relatively. The
  original is never modified.
- **Consolidate drawings…** copies every referenced PDF into the project folder
  in one explicit action.
- **Use managed copy** and **Detach from source** change the mode without
  deleting the copy.
- **Source-changed banner.** A changed reference offers **Reload**, **Use
  current**, **Relink** and **Copy into project**. A change is never accepted
  automatically. A page-count change routes to **Replace source…**.
- **Packages include managed drawings once.** Sender paths are cleared from the
  package copy.

## Integrity and project doctor

- **Shared validator.** Save checks IDs, page references, layer state, category,
  count-type, line-type and asset references, count presets, OCR state, image
  geometry and more. Errors block a normal save; warnings can be accepted.
- **Round-trip check.** The serialized project is parsed and validated again
  before the conditional write.
- **Load report.** A damaged project reports what was dropped or repaired instead
  of filtering it silently.
- **Project doctor.** Review issues by severity, open read-only, save a repaired
  copy, export path-free diagnostics and apply explicit duplicate-ID,
  dangling-reference or stale-OCR repairs. Repairs never happen silently.

## PDF interoperability

- **Optional-content layers.** An opt-in drawing-export option writes visible
  project layers as real PDF OCGs, so compatible readers can toggle them.
- **Review annotations.** An opt-in export adds standard PDF annotations for
  review in other readers. They are not an editable GridScalr project and never
  replace the flattened artwork.
- **Flattened by default.** The deterministic flattened PDF is unchanged when
  both options are off.
- **Share project package…** is the single share action and includes each
  managed drawing once.

## Compatibility and migration

The project-file schema is now **25**. Schema 23 projects migrate to schema 24
and then 25 automatically on open; older projects migrate through the same
ladder. The migration:

- builds the ordered page list from documents and excluded pages;
- assigns deterministic page IDs and maps items, layer home pages and page state;
- moves page state into page records;
- marks every existing document as a **reference** without moving or copying any
  file;
- reports invalid legacy page references instead of silently remapping them.

Managed-copy, page-identity, provenance and integrity fields are optional.
A project with zero pages is valid. Source PDFs and TIFs are never written.
