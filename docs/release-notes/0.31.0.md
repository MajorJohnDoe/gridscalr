# GridScalr 0.31.0

0.31.0 adds two neutral interface themes, **Slate** and **Graphite**, and makes
the accent colour a property of the palette instead of a jade constant compiled
into the chrome. No measurement, schedule, CSV or export capability changes, and
**the project-file schema does not change**: schema 28 stays the current
development schema and every project opens exactly as before.

This release was published on 2026-11-22.

## Slate and Graphite

Both themes come from the same four tones, and both keep white text on the
menus:

| Tone | Role | Slate | Graphite |
| --- | --- | --- | --- |
| Panel | Dock and menu base | `#343a43` | `#2c2c2e` |
| Raised | Menus, popovers, measurement flyout, controls | `#3d434d` | `#343a43` |
| Border | Borders, hover fills, scrollbar | `#444952` | `#444952` |
| Detail | Hints, dividers, scrollbar hover, dot rings | `#6e7178` | `#6e7178` |

- **Slate** (**Skiffer**) is the blue-grey reading: `#343a43` panels with white
  text and a slightly darker canvas surround.
- **Graphite** (**Grafit**) is the near-black reading: `#2c2c2e` panels, with
  `#343a43` lifting menus and controls.
- Both use a muted steel accent, `#9db0c9`, so the chrome stays neutral. The
  focus ring, active tool, selected rows, insert line, checkboxes and the
  calibrated status all use that steel instead of jade.
- `#6e7178` is 2.4:1 on `#2c2c2e`, so it stays a hint, border and detail tone.
  Secondary text uses `#b3b8c1` (Slate) and `#b0b6bf` (Graphite) and passes the
  same WCAG AA contract as every other palette.

The picker is **Settings → Preferences → General** (Swedish **Inställningar →
Inställningar… → Allmänt**) and now lists seven themes plus **System**.

## The accent follows the palette

A second accent colour was not possible before this release:

- About sixty component rules hardcoded translucent accent colours as
  `rgba(53, 194, 161, …)`. They now resolve through
  `color-mix(in srgb, var(--jade) …)`, so a border, focus ring or tinted badge
  takes the active palette's accent instead of staying green.
- The canvas selection handles, hover outline, marquee, snap marker, crosshair
  and the crop overlay hardcoded `#35c2a1`. They now read `--jade` and
  `--on-accent` once per palette, so the editor furniture matches the theme.
- The calibrated page badge moved to a readable text mix. Following the palette
  accent put its old foreground at 4.49:1 in Medium Gray; the new mix clears the
  accessibility gate in every palette.

Drawing content, layer colours and PDF exports keep their own colours. The
themes change the interface chrome and the canvas surround only.

## Landing page

The public site gains an interactive takeoff demonstration, keeps the theme tour
in both languages and now shows seven interface themes with matching
screenshots. The version, date and download links on the site are generated from
`site/release.json`, so nothing on the page names an unpublished build.

## Deliberate gaps

- There is no per-project theme. The choice is stored on this computer, like the
  language and CSV format.
- Themes cannot be imported, exported or edited in the app; the palettes ship
  with the build.
- Only the application chrome and the canvas surround are themed. The white
  drawing sheet, its content and the PDF export are unchanged.
- The neutral detail tone is deliberately not used for body text; a palette is
  free to be quiet, not unreadable.
- **System** still maps a dark OS appearance to Medium Gray and a light one to
  Light Green. It does not pick Slate or Graphite.

## No schema change

`SCHEMA_VERSION` stays **28**, the version shipped in 0.29.0. No project field,
migration step, fixture or compatibility promise changes, and a 0.31.0 project
is a schema 28 project.

## Security and dependencies

- `url` is 2.5.9, which clears **RUSTSEC-2026-0592** (a stack overflow in
  `Url::origin()` on nested `blob:` URLs, patched in 2.5.9).
- The accepted Linux-only `glib 0.18.5` advisory (`RUSTSEC-2024-0429`) is
  unchanged and stays reviewed to 2027-02-15, pending the Tauri 3 / GTK4
  migration in [#270](https://github.com/MajorJohnDoe/gridscalr/issues/270).
- `npm run check:dependencies` reports no npm findings and no unaccepted cargo
  advisory.

## Release gate baseline

Measured on the release commit with Playwright Chromium and the browser
fallback:

- Accessibility: 7 palettes × 19 surfaces plus 5 Swedish checks, 138 checks,
  0 serious/critical violations.
- Touch targets: 756 controls across 23 surfaces are at least 24 × 24 CSS px.
- UI scale: 100, 150 and 200 % keep every menu and dialog reachable; the canvas
  keeps 1292, 652 and 338 px at the three scales, with no overflow.
- Performance, reference profile with 150 pages, 15 000 items, 60 images and a
  6.9 MB serialized project: p95 edit 94.0 ms (budget 100 ms), open 30.3 ms
  (budget 10 s), autosave 1.08 s (budget 2 s), page switch 21.1 ms (budget
  100 ms), UI freeze 194.5 ms (budget 2 s), serialization p95 22.5 ms, Markups
  open 194.5 ms with 15 of 15 060 rows rendered, browser JS heap 80.2 MB.

## Upgrade notes

- There is nothing to migrate. Open a schema 28 project as before; no file is
  converted and no data is rewritten.
- An existing theme choice keeps working. If you pick Slate or Graphite, the
  choice is stored on this computer and applied without a restart.
- The only visual change outside the two new themes is the accent-tinted border,
  focus and badge colours, which now follow the selected palette's own accent
  instead of the old jade literal.
