# GridScalr 0.33.0

0.33.0 is a measured-performance and sharing release. Four performance phases
replace the guesswork around a slow edit or pan with a repeatable probe and three
targeted changes; the File menu becomes five named groups; and **File → Send &
share → Send by e-mail…** opens the drawing PDF as an unsent draft in the local
mail client. The drawing export itself is unchanged and no measurement, takeoff,
CSV or report capability moves. **The project-file schema does not change**:
schema 28 stays the current development schema and every project opens exactly as
before.

This release was published on 2026-11-24.

## Performance 1: measure first, then change

The effort started with a repeatable probe rather than an optimization. The probe
opens the demo project at a fixed 1440 × 900 viewport and DPR 1, runs 20 discrete
edits, a 5 s scripted pan and a three-step zoom, and reports frame times, named
spans, edit latency, the `serialize` share and the JS heap. It can reshape the
open project to the same default and reference profiles that
`check:performance` uses, so a phase can be compared with the previous one on the
same machine and the same shape.

Every row below was produced on the Chromium browser fallback, not the packaged
Tauri app. The profile shape is named in each row: **default** is 40 pages /
4 162 items and **reference** is 150 pages / 15 206 items. Native working-set
memory and WebView2 or WebKitGTK timing remain the manual desktop check described
in [`limitations.md`](../limitations.md#large-project-performance).

### Cheaper snapshot per edit and gesture

The baseline showed that `serialize` ran exactly once per discrete edit and took
**43.0 % of p95 edit latency on the default profile** and **53.8 % on the
reference profile**. The store now caches the serialized text of the state in
memory, pushes that cached text and serializes the new state once. Undo, redo and
a cancelled gesture move cached text instead of serializing again, and a
completed gesture pays one serialization rather than two.

The snapshot text is byte-identical to the previous format. Embedded image
payloads are cleared for one plain `JSON.stringify` and restored immediately
instead of going through a per-value replacer, and tests pin the byte identity,
one serialization per edit, one per completed gesture, none on undo or redo and
one undo step for a page reorder.

A repeat three-run session measured −26.9 % (default) and −33.8 % (reference) p95
edit, so the improvement is not a single-run artifact. The remaining `serialize`
cost is the project JSON text itself.

### Gesture-time content reuse

During a pointer pan, a wheel pan or a wheel zoom the content canvas now paints
the previous item raster with one uniform scale and translation instead of
running the full item draw. The base viewport is latched when the gesture begins
and the pixels are captured on the first frame, so repeated frames cannot
compound the transform. A pan settles at pointerup, a wheel stream 120 ms after
the last wheel event, and a touch pinch when the gesture ends; the settle drops
the raster and runs the unchanged real redraw.

The `draw-items` p95 fell **76.0 %** on the default profile and **77.5 %** on the
reference, and the sum of its spans over the scripted pan and zoom fell
**96.6 %** and **96.3 %**. The selection handles, marquee, snapping and draft
overlay still draw on every frame. Frame p95 stayed clamped at the 60 Hz interval
(16.7–16.8 ms), which is why the phase is judged on `draw-items` and the new
frames-over-20 ms counter rather than on frame p95; that counter did not regress.

### Tile cache for the primary canvas

The primary canvas now renders its crop as 512 CSS px tiles in visible-first
order, keeps a bounded **64 MiB** cache, and composes the first completed tile
immediately while later tiles fill in. A zoom stream cancels the previous view's
unfinished queue. The measured steady state was 10.2 MiB and 18 cached tiles on
both shapes, well inside the cap.

A brisker zoom therefore does less total raster work: **−29.6 %** on the default
profile and **−38.1 %** on the reference, with the per-tile `pdf-render` p95 down
**4.1 %** and **8.8 %**.

This is not a claim that the first tile is faster. Time to first visible raster
moved +7.8 % on the default shape (inside a 4.8–13.4 % run spread) and −2.4 % on
the reference (smaller than its spread), because PDF.js walks the page operator
list for each tile and the probe's crop is only about 2 × 2 tiles. The win is
bounded work and cancellation, not a general raster speedup. The gap is recorded
as F-148.

The resting screen is unchanged: the visual regression suite passed with zero
differing pixels and no baseline change. A direct canvas comparison found
differences only on antialiased edges (0.17 % of pixels at the fit view, maximum
channel delta 10), with no seam or offset. A runtime without `createImageBitmap`
or `OffscreenCanvas` keeps the full-page path from the start.

## A scannable File menu

The File menu no longer lists 20 entries on one level: five named submenus —
**Import**, **Compare**, **Send & share**, **Export** and **Maintenance** — now
hold the grouped commands, while **New project…**, **Open project…**, **Open
drawing…**, **Open recent**, the save commands, **Close project** and **Quit**
stay at the top level. Every entry keeps its action, shortcut, checked state and
disabled reason, and no keyboard shortcut is added or removed.

Moving into a group with `ArrowRight` focuses its first item, and `ArrowLeft` or
`Escape` returns focus to the group trigger rather than the previous sibling. The
File definition now lives in `src/ui/menus/fileMenu.ts`, so the menu-bar
assembler is no longer at its file-size limit.

## Send by e-mail

**File → Send & share → Send by e-mail…** runs the same drawing-export dialog as
**File → Export → Drawing PDF…** and then opens a new, unsent draft in the local
mail client with `<project>-markups.pdf` attached. Page range, crop, visible
layers, labels, the calibration line, the legend, optional reader layers and
review annotations follow the same rules; hidden items and hidden layers are
never attached. The attachment is written to the app-cache `mail-outbox/`
folder, which keeps the ten most recent PDFs. The project file and the source
drawings are never attached or modified.

| Platform | Draft path |
| --- | --- |
| Windows | Simple MAPI through the default MAPI client, usually Outlook; `outlook.exe /a` when Simple MAPI is unavailable |
| macOS | A visible Mail.app draft through `osascript`; the first launch may ask for Automation permission |
| Linux | `xdg-email --attach`, with `thunderbird -compose attachment=…` as the fallback |

A drawing above **20 MB** is a warning, not a refusal: **Continue** attaches the
same PDF, **Export to disk instead** writes it through the normal save dialog,
and **Cancel** does nothing. If no client opens, GridScalr still names the
written PDF and offers **Show file**, so a failed launch is never silent.

The feature is desktop-only and disabled in the browser fallback. Webmail is not
supported because a `mailto:` link cannot attach a file, and nothing is sent
automatically.

**No mail client was verified on hardware for this release.** The shared PDF
builder, the menu state, the attachment choices, the Rust argument builders and
the path guard are covered by automated tests, but a real draft on Outlook,
Mail.app and Thunderbird remains the manual checklist in
[`testing.md`](../testing.md#manual-send-by-email-checklist). The client may show
its own profile, security or attachment prompt, and closing the draft without
sending is the client's choice.

## Limits

- The performance rows come from the browser fallback in Chromium. The packaged
  app, WebView2 and WebKitGTK timing, and native working-set memory stay the
  manual desktop check.
- The gesture reuse and the tile cache apply to the primary canvas. The
  read-only reference pane and split view keep the full-page redraw path, so
  their pan cost is unchanged (F-147).
- PDF.js re-walks the page operator list for each tile, so the first tile on a
  small crop can cost about as much as the monolith (F-148).
- The tile path was exercised in Chromium only. WebKitGTK is feature-detected and
  falls back to the full page, but the tile path there is unverified (F-149).
- Send by e-mail has no webmail path and no verified hardware run; see the
  manual platform checklist above.
- The build artifacts remain unsigned and un-notarized, and a physical macOS
  install is still unverified.

## No schema change

`SCHEMA_VERSION` stays **28**, the version shipped in 0.29.0. There is no
migration step, fixture or compatibility promise change, and the project file
format, export formats and shortcut catalogue are untouched.

## Upgrade notes

- There is nothing to migrate. Open a schema 28 project as before; no file is
  converted and no data is rewritten.
